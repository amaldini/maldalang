# The MALDA name

MALDA's code and documentation are open source, offered under the
[MIT License](LICENSE-MIT) or the [Apache License 2.0](LICENSE-APACHE). The **name**
"MALDA" is a different thing, and neither licence grants rights to it. Apache-2.0 says
so explicitly in its section 6; MIT is silent, which amounts to the same result,
because a copyright licence does not transfer trademark rights either way.

This page exists so nobody has to guess where the line falls. The aim is narrow: keep
"MALDA" meaning *this* project, so that a user who downloads something called MALDA
knows what they are getting. Everything that does not undermine that is fine.

## You do not need permission to

- Say that your software is written in MALDA, targets MALDA, or embeds MALDA.
- Describe your library, tool, plugin or editor extension as "for MALDA",
  "MALDA-compatible" or "built with MALDA".
- Write and sell books, courses, tutorials, blog posts, videos or training about
  MALDA, and put the word MALDA in the title.
- Redistribute MALDA unmodified, under its own name, as part of a package manager, a
  distribution or a container image.
- Run user groups, conferences, meetups and community sites about MALDA.
- Use the name in academic papers, comparisons and reviews, favourable or not.

In short: **using the word MALDA to refer to MALDA is always allowed.** Trademark law
calls this nominative use, and no policy can or should restrict it.

## Please ask first before

- Naming your own product, company, service or paid offering "MALDA" or something
  close enough to be mistaken for it.
- Releasing a **modified** version of MALDA still called "MALDA". Fork freely — the
  licences guarantee that right — but give the fork its own name, and say plainly that
  it is derived from MALDA. This is the one restriction that actually matters: a
  modified MALDA circulating under the same name is how a language ends up with
  incompatible dialects that all claim to be the original.
- Registering domain names, package names or social media handles built around the
  name in a way that looks official.
- Presenting anything as "official", "certified" or endorsed by the MALDA project.
- Using the name or any project logo in a way that suggests a partnership that does
  not exist.

Asking is informal: open an issue at
<https://github.com/amaldini/maldalang/issues> and describe the use. The default answer for
anything made in good faith is yes.

## Naming a fork or a derived work

Good: *"Foo, a MALDA-compatible language"*, *"Foo, based on MALDA"*, *"Foo for MALDA"*.

Not good: *"MALDA Pro"*, *"MALDA Enterprise"*, *"MALDA++"*, *"Official MALDA
Distribution"* — these read as versions of this project rather than separate ones.

## Status of the name

**MALDA™** and any MALDA logos are trademarks of Andrea Maldini, used continuously to
identify this project, its releases and its documentation. Those rights are asserted,
and releasing the code under permissive licences does not abandon them.

The project marks the name with ™ on the most prominent use in a document — the README
title, the manual masthead, the book cover — and writes it plainly everywhere else.
There is no need for you to reproduce the symbol when you mention MALDA.

This page describes how the project expects its name to be used. It is a statement of
policy: it does not waive, limit or exhaust any right available under applicable law.
