# MALDA 1.0.40

Patch after 1.0.39: the interpreter and both transpilers run faster, the
three backends agree on more programs, and the CLI gains `malda fmt`,
`malda lint`, and a JavaScript capability check that lists every
host-only feature before emit.

## Highlights

- **Faster interpreter and transpile** — `return`, `break`, and
  `continue` no longer throw on the interpreter hot path. Transpiled C#
  types `int` / `double` locals, emits sync and typed twins for
  functions and methods, and skips defer frames around blocks that
  cannot `defer`. JavaScript skips redundant truthiness and float
  coercions. `benchmarks/runtime` times each backend.
- **Backend parity** — seeded programs must print the same on the
  interpreter, C#, and JavaScript (CI, plus a nightly fuzz job).
  Fixes include `continue` in nested loops, banker's rounding for
  `math.round` on JS, print and interpolation formatting, `finally`
  after a `catch` that leaves by `break` / `continue` / `return` /
  `throw`, user bindings that shadow flat built-ins, calls of
  functions stored in object and dict literals, and function values
  of any arity in C#.
- **`malda fmt`** — comment-preserving formatter for the CLI, the
  language server, and the Desktop IDE. It normalizes indentation and
  spacing and leaves the token stream unchanged.
- **`malda lint`** — gotchas from the language pack as `ML0xxx`
  findings, with suppressions and LSP diagnostics. `malda lint --fix`
  rewrites deprecated flat stdlib aliases (`print(` to `io.print(`).
  Examples and Templates now use the namespaced names.
- **JavaScript stdlib and pre-check** — the pure stdlib matches the
  interpreter. `--mode js` / `pwa` reports every host-only use
  (`JS0001`–`JS0014`) before emit; host-library helpers stay on the
  exception list.
- **Parser** — anonymous `function (params) { ... }`, one trailing
  comma in parameter lists, and `context` / `suite` / `policy` /
  `within` as identifiers outside their declaration shape. Every
  parser-built AST node has a source position. Diagnostics from an
  included file name that file and line.
- **Neural nets** — `state()` / `load(state)` save and restore weights
  on every layer. A mismatched state changes nothing.
- **C# transpile** — UTF-8 stdout; prompts with `tools:` / `gather:`
  no longer throw while building the tool list; Spectre
  `progress` / `status` callbacks go through the runtime built-ins;
  `math.abs` / `min` / `max` return `int` when every argument is
  `int`. Building `MaldaLang.Compiler` refreshes the CLI, so
  `malda compile` does not keep a stale transpiler.
- **Workflows** — `writeFileBase64`, `ensureDir`, and `insertAtLine`
  are on the WF1002 deny-list with the other file writes.
- **Examples** — hilly circuits in the 3D neural race; a seeded RANSAC
  line-fit under Algorithms.

## Requirements

Same as 0.1.0:

- .NET 8 SDK
- Windows for the Desktop IDE; CLI / Web IDE / LSP are intended to work wherever .NET 8 does

## Install without sources

Download `malda-1.0.40-win-x64.zip` (CLI + Desktop IDE) or `malda-1.0.40-linux-x64.zip`
(CLI only) from the GitHub Release assets, unzip, and run:

```bash
# Windows
malda.bat Examples\Basics\first_look.malda
MaldaDesktop.bat

# Update an existing win-x64 install in place:
powershell -File scripts\update-local-win-x64-release.ps1 -Force
# or, in the Desktop IDE: Help → Update Installation...

# Linux
./malda Examples/Basics/first_look.malda
```

## Quick start (from source)

```bash
git clone https://github.com/amaldini/maldalang.git
cd maldalang
git checkout v1.0.40
dotnet build MaldaLang
dotnet run --project MaldaLang -- Examples/Basics/first_look.malda
```

## Notes

- Language Spec remains **Final 1.0** (`docs/spec/malda-language-1.0.md`).
  Toolchain 1.0.40 is not a new spec line.
- Out-of-range reads, division by zero, `int("abc")`, and writes past
  the end of an array still differ by backend. The fuzz skips them
  until that is decided.
- See also [`docs/releases/v1.0.39.md`](v1.0.39.md).
