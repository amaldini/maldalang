# MALDA 1.0.11

Patch after 1.0.10: JavaScript-mode shader kernels (MALDA to GLSL) and
a thicker three.js chapter in the Reference Manual.

## Highlights

- **`@shader()` kernels** — Typed MALDA functions marked `@shader()`
  compile to GLSL through `glsl.compile({ ... })` in JavaScript mode.
  This is a JS compile-time subset, not a fourth execution backend.
  Host MALDA still owns the `three.*` loop and uniforms; kernels own
  the per-pixel work. Interpreter and C# transpile skip those functions.
- **GLSL types stay GLSL** — `vec2` / `vec3` / `vec4` are type hints
  copied into the shader. Outside `@shader()`, `var p: vec3` is an
  unknown-hint Error. Host uniforms stay arrays such as `[x, y, z]`.
- **IDE rename on kernels** — Because kernels are ordinary `function`
  declarations, rename / find-references / outline see identifiers.
  String keys in `glsl.compile` (`functions: ["hitSphere"]`,
  `main: "fragmentMain"`) are not rewritten.
- **Reference Manual 26.10** — The three.js scene API now has a starter
  listing, `dtMs` loop guidance, and host loading order. Shader contract
  is **26.10.1**. Example: `Examples/Web/js/three_shader_raytracer.malda`.

## Requirements

Same as 0.1.0:

- .NET 8 SDK
- Windows for the Desktop IDE; CLI / Web IDE / LSP are intended to work wherever .NET 8 does

## Install without sources

Download `malda-1.0.11-win-x64.zip` (CLI + Desktop IDE) or `malda-1.0.11-linux-x64.zip`
(CLI only) from the GitHub Release assets, unzip, and run:

```bash
# Windows
malda.bat Examples\Basics\first_look.malda
MaldaDesktop.bat

# Update an existing win-x64 install in place:
powershell -File scripts\update-local-win-x64-release.ps1 -Force

# Linux
./malda Examples/Basics/first_look.malda
```

## Quick start (from source)

```bash
git clone https://github.com/amaldini/maldalang.git
cd maldalang
git checkout v1.0.11
dotnet build MaldaLang
dotnet run --project MaldaLang -- Examples/Basics/first_look.malda
```
