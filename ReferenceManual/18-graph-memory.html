18. GraphMemory

GraphMemory is a built-in class that provides semantic memory capabilities for AI agents. It combines a knowledge graph (for relationship modeling) with a vector database (for semantic search) to enable agents to remember facts, understand relationships, and retrieve relevant context based on semantic similarity.

GraphMemory is particularly powerful when used with the Agent class, automatically injecting relevant memories into agent prompts to provide context-aware responses across multiple sessions.

18.1 Creating a GraphMemory

GraphMemory instances are created with the new GraphMemory() constructor:

var memory = new GraphMemory();
memory.initialize();

After creation, you must call initialize() before using other methods. You can optionally specify vector dimension and precision:

// Initialize with default settings (384 dimensions, single precision)
var memory = new GraphMemory();
memory.initialize();

// Initialize with custom dimension
var memory2 = new GraphMemory();
memory2.initialize(512);  // 512-dimensional vectors

// Initialize with custom dimension and precision
var memory3 = new GraphMemory();
memory3.initialize(768, "double");  // 768 dimensions, double precision

Constructor:

  • new GraphMemory() - Creates a new GraphMemory instance (no arguments)

Initialize Parameters:

  • initialize() - Initialize with defaults (384 dimensions, "single" precision, uses embedBagOfWords)
  • initialize(dimension) - Initialize with custom dimension (integer, must be > 0)
  • initialize(dimension, precision) - Initialize with custom dimension and precision ("single" or "double")
  • initialize(dimension, precision, embeddingFunction) - Initialize with custom embedding function for neural network embeddings

Custom Embedding Functions

By default, GraphMemory uses embedBagOfWords for text embeddings. For better semantic understanding, you can provide a custom embedding function that uses neural network embeddings (e.g., from LlamaEmbedder).

Why use neural embeddings with GraphMemory?

  • Better Semantic Matching: Neural embeddings understand that "I work as a developer" and "My job is programming" are semantically similar, even with no word overlap.
  • Context Understanding: Queries like "What do I do for work?" will find relevant memories about professions, even if the exact words don't match.
  • Improved Agent Memory: AI agents using GraphMemory with neural embeddings can retrieve more relevant context, leading to better responses.
  • Cross-Domain Understanding: Neural models trained on diverse text can understand relationships across different domains and topics.

Example:

// Use neural embeddings for better semantic understanding
var embedder = new LlamaEmbedder("path/to/embedding-model.gguf");
function neuralEmbed(text) {
    return embedder.getEmbeddings(text);
}

var memory = new GraphMemory();
memory.initialize(384, "single", neuralEmbed);  // Custom embedding function
memory.remember("I'm a software engineer");
memory.remember("I code in Python");

// Query finds semantically related memories
var results = memory.query("What is my job?", 5);
// Finds both facts because "software engineer" and "code" are semantically
// related to "job" even though the words don't match exactly

18.2 Remembering Facts

The remember() method stores facts in the memory system. Facts are indexed in the vector database for semantic search and stored in the knowledge graph for relationship tracking.

var memory = new GraphMemory();
memory.initialize();

// Remember a simple fact
var nodeId1 = memory.remember("My name is Alice");
print(nodeId1);  // "node_0"

// Remember a fact with context
var nodeId2 = memory.remember("I prefer dark mode", "UI preferences");
print(nodeId2);  // "node_1"

// Remember structured data
var fact = dict {
    "type": "preference",
    "value": "dark mode",
    "category": "UI"
};
var nodeId3 = memory.remember(fact, "User preferences");
print(nodeId3);  // "node_2"

Parameters:

  • remember(fact) - Store a fact (string or object)
  • remember(fact, context) - Store a fact with optional context (string)
  • remember(fact, context, metadata) - Store with structured metadata (object). Supported fields: phase, iteration, type (e.g. progress, decision, file, error, episodic, semantic), source, scope (e.g. chat:123; omit for global), category (single string), tags (array of strings or CSV; trimmed, lowercased, deduped and appended to the indexed description for BM25/vector search)
// Structured progress note (used by Ralph Wiggum and custom loops)
memory.remember(
    "Implemented snake movement",
    "validation=true; files=game.js",
    { "phase": "movement", "iteration": 2, "type": "progress", "source": "ralph" }
);

Returns: A string node ID (e.g., "node_0") that can be used with findRelated()

How it works:

  • Generates a unique node ID for the fact
  • Creates a description from the fact and context for vector indexing
  • Stores the fact in the knowledge graph with metadata (fact, context, timestamp)
  • Indexes the description in the vector database for semantic search
  • Deduplicates near-identical facts (similarity ≥ 0.95 and same fact text or identical indexed description): updates the existing node instead of creating a duplicate; paraphrases remain separate nodes and can still be auto-linked
  • Automatically links the new node to up to five semantically similar existing memories (see below)
  • Returns the node ID for later reference

18.2.1 Automatic semantic linking

After each remember(), GraphMemory searches the vector index for similar prior entries. When cosine similarity is at least 0.6, it adds bidirectional related_to edges in the knowledge graph (weighted by similarity). This connects conversational memories without extra API calls — the same pattern used in agent-memory research (e.g. Zettelkasten / A-MEM style note linking).

var memory = new GraphMemory();
memory.initialize();

var id1 = memory.remember("My name is Alice");
memory.remember("Alice is my name");   // auto-linked to id1 when similar enough

var cluster = memory.findRelated(id1);
// cluster includes both facts via graph traversal

Code-structure edges from analyzeFile() use a separate contains edge type; conversational links use related_to.

18.3 Querying Memory

The query() method performs semantic search to find relevant memories. It uses vector similarity to find similar facts, then uses graph traversal (BFS) to find related nodes.

var memory = new GraphMemory();
memory.initialize();

// Store some facts
memory.remember("My name is Alice");
memory.remember("I prefer dark mode");
memory.remember("I work as a software engineer");
memory.remember("I like Python programming");

// Query for relevant memories
var results = memory.query("What are my preferences?");
foreach (var result in results) {
    if (result.fact != null) {
        print(result.fact);
    }
}

// Query with custom result limit
var topResults = memory.query("programming languages", 3);  // Top 3 results

Parameters:

  • query(queryString) - Search for relevant memories (default: top 5 results)
  • query(queryString, maxResults) - Search with custom result limit (integer)
  • query(queryString, maxResults, options) - Search with hybrid/recent options (object)
  • query(queryString, options) - When the second argument is an object, it is treated as options (default maxResults: 5)

18.3.1 Hybrid query (semantic + recent)

Pass an options object as the second or third argument to combine semantic search with the most recent structured entries. This is useful when conversation history is reset each iteration (e.g. Ralph Wiggum) but you still need deterministic continuity.

var options = {
    "recentCount": 3,
    "hybrid": true,
    "phase": "user-auth",
    "type": "progress"
};
var results = memory.query("files changed decisions", 5, options);
// Merges up to 3 recent matching entries with up to 5 semantic matches (deduplicated)

Options fields:

  • recentCount (integer) - Include the N most recent entries (by timestamp)
  • hybrid (boolean) - When true (default if recentCount > 0), merge recent + semantic results
  • phase (string) - Filter by metadata phase
  • type (string) - Filter by metadata type
  • maxResults (integer) - Override semantic result limit when using query(query, options)
  • minScore (number, default 0) - Minimum vector similarity (0–1) for a semantic hit to seed graph expansion; weak matches are excluded before BFS
  • scope (string) - Filter by metadata scope; entries with scope: global or no scope are visible in every scope (legacy mode)
  • scopeHierarchy (array) - Hierarchical scopes, e.g. ["chat:123", "project:foo", "global"]; a node matches when its scope is in the list. Auto-built from scope + scopeParent / MALDA_MEMORY_SCOPE_PARENT when omitted.
  • scopeParent (string) - Parent scope included in the auto hierarchy (e.g. project:foo)
  • excludeType (string) - Exclude entries whose metadata type matches (semantic path only in hybrid queries)
  • maxDistance (integer, default 0 = unlimited) - Limit graph BFS expansion to N hops from each semantic hit
  • synapse (boolean, default true) - Re-rank semantic hits using lightweight type/recency boosts: favors semantic, progress, and decision entries; penalizes episodic; adds a small recency bonus
  • hybridLexical (boolean, default false) - Blend vector similarity with lexical scoring on fact/description (helps proper nouns, paths, IDs)
  • lexicalMode (string) - lite (default token overlap) or bm25 (inverted-index BM25). Also: bm25: true or MALDA_MEMORY_LEXICAL_MODE=bm25.
  • lexicalWeight (number, default 0.25) - Weight of the lexical score when hybridLexical is true
  • lexicalMinScore (number or "auto", default 0.15) - Minimum normalized lexical/BM25 score for a node to enter the hybrid candidate set. Use 0 to always admit lexical hits. With "auto" and hybridLexical, the floor is 0 when the vector channel returns no useful seeds (empty/failed searchSimilar), otherwise 0.15.
  • tags (array or CSV string) - Keep only nodes whose metadata tags match the filter. Nodes without tags never match a non-empty filter.
  • tagsMode (string, default any) - any: match if at least one filter tag is present; all: require every filter tag.
  • diagnostics (boolean, default false) - When true, getLastQueryDiagnostics() includes richer drop samples (up to 5). A lightweight summary is always stored after each query.
  • includeTypes (array or comma-separated string) - Allow only listed metadata type values (works with or instead of excludeType)
  • rerank (boolean, default false) - Enable reranking over retrieved candidates.
  • rerankMode (string) - llm (default, uses rerankClient/rerankModel), cross (local BM25 + lexical + bigram + vector blend, no LLM call), or onnx (BERT-style ONNX cross-encoder when rerankModelPath / MALDA_MEMORY_RERANK_MODEL_PATH points to model.onnx with vocab.txt; falls back to cross when unavailable).
  • rerankModelPath (string) - Path to ONNX cross-encoder model file or directory containing model.onnx and vocab.txt.
  • rerankTopK (integer, default 20) - Number of semantic candidates considered before rerank.
  • rerankModel / rerankClient - Select model or inject a client instance for reranking.
  • rerankScores (array) - Test injection scores [{ nodeId, score }] that bypass model calls.
  • explain (boolean, default false) - When true, each result includes score and an explain object with vectorScore, lexicalScore, combinedScore, synapseScore, importanceBonus, supersededPenalty, finalScore, tags, and (when a tags filter was used) tagsMatched.
  • grounded (boolean, default false) - When true, return a grounded.wrap wrapper instead of the hit array. See §18.3.15.

query(...) returns an array of memory nodes unless grounded: true is set (then a wrapper — §18.3.15). After each query, call getLastQueryDiagnostics() for a summary object (null before the first query) with fields such as vectorCandidates, bm25Candidates, afterFilters, returned, droppedByLexicalMinScore, droppedByTagFilter, droppedByTypeFilter, lexicalMinScoreApplied, lexicalMinScoreMode (number | auto-weak-vector | auto-default), and embedReady.

var hits = memory.query("plugin campi", 5, {
    "hybridLexical": true,
    "lexicalMode": "bm25",
    "lexicalMinScore": "auto",
    "tags": ["bom", "plugin"],
    "tagsMode": "any",
    "diagnostics": true,
    "explain": true
});
var diag = memory.getLastQueryDiagnostics();
print(diag.returned);
print(diag.lexicalMinScoreMode);

18.3.2 Recent entries (getRecent)

Returns the most recent memory entries sorted by timestamp, without semantic search.

var recent = memory.getRecent(5);           // last 5 entries
var phaseRecent = memory.getRecent(3, "movement");  // last 3 for phase "movement"
var typed = memory.getRecent(5, "movement", "progress");  // optional type filter
var scoped = memory.getRecent(5, "", "", "chat:123");    // optional scope filter (empty phase/type = no filter)

Returns: An array of memory objects, each containing:

  • fact - The original fact that was remembered
  • context - Optional context (if provided)
  • timestamp - When the fact was stored (ISO 8601 format)
  • phase, iteration, type, source, scope - Optional metadata fields when stored via remember(..., metadata)

How it works:

  1. Scans stored memory metadata (this is not a semantic or vector search; use query() for that)
  2. Keeps entries that match the optional phase, type, and scope filters (empty string means no filter for that argument)
  3. Sorts remaining entries by timestamp, newest first
  4. Returns up to count memory objects in that order

18.3.3 Forgetting entries (forget)

Removes a memory node by ID from the knowledge graph, vector index, and metadata store. Connected edges are removed with the node.

var nodeId = memory.remember("Outdated fact");
var removed = memory.forget(nodeId);  // true if the node existed

For batch resets, use:

  • forgetByScope(scope, options?) - Prunes entries in a specific scope (optional type filter).
  • startKbWatch(dir, pattern?, options?) - Watches a directory and runs reindexDocuments on changes (debounced). Options: scope, savePath, pattern, debounceMs.
  • stopKbWatch() - Stops the active KB file watcher for this GraphMemory instance.
  • forgetByCategory(category, options?) - Removes entries by metadata category (optional scope filter).
  • forgetByTag(tag, options?) - Removes entries whose metadata tags contain tag (optional scope filter).
  • getLastQueryDiagnostics() - Returns diagnostics from the most recent query call, or null if none yet.

18.3.4 Indexing document files (indexDocuments)

Loads files matching a glob pattern (same as loadDocuments) and stores each file (or chunk) as a semantic memory with type: semantic, source: file, and configurable scope (default global). Large files are split into chunks by default (chunkSize: 2000, overlap: 100). Chunk context is path#chunk-N.

var count = memory.indexDocuments("**/*.md", "./docs");
var chunked = memory.indexDocuments("**/*.md", "./docs", {
    "chunkSize": 1500,
    "overlap": 100,
    "scope": "global",
    "changedOnly": true
});
print("Indexed " + count + " chunks");

With changedOnly: true, files whose fileHash metadata matches the current content are skipped; changed files replace prior chunks for the same filePath.

18.3.5 Memory stats (stats)

Returns an object with nodes, edges, byType, byScope, oldest, and newest timestamps (ISO 8601).

var s = memory.stats();
print(s.nodes);
print(s.byType.semantic);

18.3.5a Health check (validate)

Checks consistency between metadata, graph nodes, vector index entries, and edges. Returns { ok, issues, counts }. Issue types: metadata_without_graph, graph_without_metadata, vector_without_node, node_without_vector, dangling_edge.

var report = memory.validate();
if (!report.ok) {
    print(report.issues.length + " issues");
}

18.3.5b Rotating backups on save()

Before overwriting artifacts, optionally copy the current files to {base}.backup.{yyyy-MM-dd-HHmmss}.graph.json (and matching .metadata.json / .vectordb.bin) and prune older backups.

memory.save("~/.malda/memory/assistant", { "backup": true, "maxBackups": 5 });
// Or: MALDA_MEMORY_BACKUP=true, MALDA_MEMORY_MAX_BACKUPS=5

18.3.6 Node lookup and in-place update

Use getNode, hasNode, and update to read or revise an existing memory without creating a new node ID.

var nodeId = memory.remember("My name is Alice", "", { "type": "semantic" });
if (memory.hasNode(nodeId)) {
    var node = memory.getNode(nodeId);
    print(node.fact);
}
memory.update(nodeId, "My name is Bob");  // refreshes vector index; keeps context/metadata when omitted
var revised = memory.getNode(nodeId);
print(revised.fact);
  • getNode(nodeId) - Returns the memory object, or null if missing
  • hasNode(nodeId) - Returns true if the node exists
  • update(nodeId, fact, context?, metadata?) - Re-indexes the node in place; omitted context and metadata fields are preserved from the existing entry

18.3.7 Episodic consolidation (consolidate)

Distills recent episodic turns into a single semantic summary node with derived_from edges back to the source episodics. Processed episodics are marked consolidated: true so they can be pruned safely later.

var result = memory.consolidate({
    "scope": "chat:123",
    "minEpisodic": 3,
    "maxEpisodic": 30
});
print(result.semanticNodesCreated);
print(result.semanticNodeId);

18.3.8 Batch pruning (prune)

Removes matching nodes in bulk. Requires at least one filter in options: type, scope, phase, source, or olderThanDays. Optional consolidated (boolean) keeps only nodes with/without consolidated: true. Returns the number of nodes removed.

var removed = memory.prune({
    "type": "episodic",
    "olderThanDays": 30,
    "scope": "chat:123",
    "consolidated": true
});
print("Removed " + removed + " memories");

18.3.9 Memory size limits (enforceLimits)

When total node count exceeds maxNodes, removes the oldest matching entries (default type: episodic). Returns the number of nodes removed.

memory.enforceLimits({ "maxNodes": 5000, "type": "episodic", "scope": "chat:123" });

18.3.10 Portable bundles (exportBundle / importBundle)

exportBundle(path) writes the same artifacts as save(path) plus a {base}.bundle.json manifest. importBundle(path) validates the manifest and artifacts, then restores graph, metadata, and vector index (same as load(path)).

var manifest = memory.exportBundle("team_memory");
memory.importBundle("team_memory");

18.3.11 LLM reflection (reflect)

reflect(options?) consolidates unconsolidated episodic turns into semantic facts using an LLM-oriented extraction flow. It accepts optional test injection with facts (array of { fact, confidence, category }) to bypass external model calls.

var result = memory.reflect({
    "scope": "chat:123",
    "minEpisodic": 3,
    "maxEpisodic": 30,
    "model": "openai/gpt-4o-mini"
});
print(result.factsCreated);
print(result.episodicsMarked);
  • Creates semantic nodes for facts with confidence >= 0.7 (metadata: source: reflect, confidence, category)
  • minConfidence in options overrides the default threshold; client injects an existing LLM client instance.
  • With resolveConflicts (default true), highly similar semantic facts compare confidence and add supersedes only when the new fact is stronger.
  • Adds derived_from edges from each reflected semantic node to source episodics
  • Marks source episodics as consolidated: true unless dryRun: true
  • Falls back to consolidate(options) on reflection parsing/LLM errors

18.3.11a Background reflection (reflectAsync)

reflectAsync(options?) schedules the same work as reflect() on a background thread and returns immediately with { scheduled, pending }. Pass savePath in options to persist artifacts after reflection completes. If a reflect job is already running, returns pending: true.

memory.reflectAsync({
    "scope": "chat:123",
    "client": llmClient,
    "savePath": "~/.malda/memory/assistant"
});

18.3.12 Reindexing documents (reindexDocuments)

reindexDocuments(pattern, dir?, options?) wraps indexDocuments with changedOnly: true by default and returns detailed counters:

var r = memory.reindexDocuments("**/*.md", "./docs", { "scope": "global" });
print(r.indexed);
print(r.skipped);
print(r.removed);

18.3.13 Retrieval evolution

Memory retrieval now tracks importance, accessCount, and lastAccessed metadata, supports activation controls (activation, activationDecay), MMR diversity (diversity), and exclusion by node IDs (excludeNodeIds). Semantic updates may create supersedes edges; superseded nodes are down-ranked or filtered during query.

18.3.14 CLI maintenance (malda memory)

Use the CLI to inspect and maintain assistant memory at ~/.malda/memory/assistant (override with --path).

malda memory stats --json
malda memory validate --json
malda memory reindex --dir ./kb --pattern "**/*.md"
malda memory prune --type episodic --older-than-days 30 --consolidated
malda memory reflect --scope chat:123 --min-confidence 0.75
malda memory export-bundle -o ./backup/team_memory
malda memory watch --dir ./kb --pattern "**/*.md"
malda memory download-rerank

download-rerank fetches the default Hugging Face cross-encoder (cross-encoder/ms-marco-MiniLM-L6-v2) into ~/.malda/models/cross-encoder (model.onnx + vocab.txt). Override the repo with MALDA_CROSS_ENCODER_MODEL.

18.3.15 Grounded ASK (ask / grounded.wrap)

Citations from GraphMemory hits are not a first-class match value. Opt in so the retrieval result is a wrapper with value, citations ({ source, id?, span? }), and sourced:

var memory = new GraphMemory();
memory.initialize();
memory.remember("Alice prefers dark mode", "", { "source": "notes.md" });
var g = memory.ask("What are Alice's preferences?", 5, { "minScore": 0 });
print(g.sourced);
print(g.citations[0].source);
print(g.value.length);

// Same wrap on the existing query path:
var also = memory.query("preferences", 5, { "minScore": 0, "grounded": true });
var manual = grounded.wrap(also.value, also.citations);

ask(query, maxResults?, options?) uses the same retrieval as query, then wraps hits. Plain query without grounded: true still returns an array. There is no flat grounded() alias. Example: Examples/Memory/grounded_ask.malda.

18.4 Finding Related Nodes

The findRelated() method returns memory objects reachable from a node via graph traversal (BFS over outgoing edges, including auto-linked related_to neighbors):

var memory = new GraphMemory();
memory.initialize();

var nodeId1 = memory.remember("My name is Alice");
memory.remember("Alice is my name");

// Find memories linked to nodeId1 (auto-linked when similar)
var related = memory.findRelated(nodeId1);
print(related.length);  // e.g. 1 — the second fact

Parameters:

  • findRelated(nodeId) - Find related nodes (default: max distance 2)
  • findRelated(nodeId, maxDistance) - Find related nodes with custom max distance (integer)

Returns: An array of memory objects related to the specified node

18.5 Code Element Management

GraphMemory can store and analyze code elements, making it useful for codebase understanding and relationship mapping.

18.5.1 Adding Code Elements

The addCodeElement() method stores code elements (functions, classes, etc.) in the memory:

var memory = new GraphMemory();
memory.initialize();

var elementData = dict {
    "type": "function",
    "name": "createUser",
    "description": "Creates a new user in the database"
};
var nodeId = memory.addCodeElement("UserService.createUser", elementData);
print(nodeId);  // "code_UserService.createUser"

Parameters:

  • addCodeElement(elementId, elementData) - Store a code element
  • elementId (string): Unique identifier for the code element (e.g., "UserService.createUser")
  • elementData (object): Metadata about the code element (type, name, description, etc.)

Returns: A string node ID (e.g., "code_UserService.createUser")

18.5.2 Finding Code Relationships

The findCodeRelationships() method finds all relationships (edges) connected to a code element:

var memory = new GraphMemory();
memory.initialize();

// Add code elements
memory.addCodeElement("UserService.createUser", dict { "type": "function", "name": "createUser" });
memory.addCodeElement("UserService.deleteUser", dict { "type": "function", "name": "deleteUser" });

// Find relationships for a code element
var relationships = memory.findCodeRelationships("UserService.createUser");
foreach (var rel in relationships) {
    print("Type: " + rel.type);
    if (rel.target != null) {
        print("Target: " + rel.target);
    }
    if (rel.source != null) {
        print("Source: " + rel.source);
    }
}

Parameters:

  • findCodeRelationships(codeElement) - Find relationships for a code element (string)

Returns: An array of relationship objects, each containing:

  • type - The relationship type (from edge properties)
  • target - Target node (if outgoing edge)
  • source - Source node (if incoming edge)

18.5.3 Analyzing Files

The analyzeFile() method automatically extracts code structure from a MALDA source file and stores it in memory:

var memory = new GraphMemory();
memory.initialize();

// Analyze a MALDA source file
var elementCount = memory.analyzeFile("path/to/file.malda");
print("Found " + elementCount + " code elements");

// The method extracts:
// - Classes and their relationships
// - Functions and their signatures
// - File structure and containment relationships

Parameters:

  • analyzeFile(filePath) - Analyze a MALDA source file (string path)

Returns: An integer count of code elements extracted and stored

What it extracts:

  • Classes with their names and file locations
  • Functions with their names, signatures, and file locations
  • File-to-element relationships (file contains class/function)
  • All stored as nodes in the knowledge graph with proper relationships

18.6 Persistence

GraphMemory supports saving and loading memory state to/from disk for persistence across sessions.

18.6.1 Saving Memory

The save() method saves the entire memory state to disk:

var memory = new GraphMemory();
memory.initialize();
memory.remember("Important fact");

// Save to disk (creates three files)
memory.save("my_memory");

// Creates:
// - my_memory.graph.json (knowledge graph)
// - my_memory.vectordb.bin (vector database)
// - my_memory.metadata.json (node metadata)

Parameters:

  • save(filePath) - Save memory to disk. For normal paths (e.g. my_memory.mem), the extension is stripped to form the base path. Dot-prefixed basenames (e.g. .ralph-memory) are used as-is — required on Windows so artifacts are not written to .graph.json in the parent folder.

Files Created:

  • {basePath}.graph.json - Knowledge graph in JSON format (nodes and edges, including related_to links)
  • {basePath}.vectordb.bin - Vector database in binary format
  • {basePath}.metadata.json - Node metadata in JSON format

18.6.2 Loading Memory

The load() method restores a previously saved memory state: graph (with edges), vector index, and node metadata. The embedding calculator is re-initialized so query() and future remember() calls work after reload.

var memory = new GraphMemory();

// Load from disk (automatically initializes if needed)
memory.load("my_memory");

// Memory is restored — facts, graph links, and vector index
var results = memory.query("previous facts");
var linked = memory.findRelated("node_0");  // graph edges persist across save/load

Parameters:

  • load(filePath) - Load memory from disk (string path, extension is ignored)

Note: Call initialize(dimension, precision, embeddingFunction) before load() when using a custom embedder; load() preserves the embedding function across its internal re-initialization. The personal assistant defaults to embedHash (384 dimensions) and supports MALDA_MEMORY_EMBED or config.agents.memory.embed values hash, bow, or llama (see 31. Personal Assistant).

18.7 Graph Export and Import

GraphMemory provides methods to export and import the knowledge graph separately from the full persistence system.

18.7.1 Exporting the Graph

var memory = new GraphMemory();
memory.initialize();
memory.remember("Test fact");

// Export graph as JSON string
var graphJson = memory.exportGraph();
print(graphJson);

// Can be used for:
// - Sharing knowledge graphs between systems
// - Backup and restore
// - Graph analysis in external tools

Returns: A JSON string representation of the knowledge graph

18.7.2 Importing the Graph

var memory = new GraphMemory();
memory.initialize();

// Import graph from JSON string
memory.importGraph(graphJson);

// Graph structure is now restored
// Note: Vector database and metadata are not restored by importGraph()

Parameters:

  • importGraph(graphJson) - Import graph from JSON string

Note: importGraph() only restores the graph structure, not the vector database or metadata. Use load() for complete restoration.

18.8 Clearing Memory

The clear() method removes all stored memories and resets the memory system:

var memory = new GraphMemory();
memory.initialize();
memory.remember("Some fact");

// Clear all memories
memory.clear();

// Memory is now empty (but still initialized)
// You can start storing new facts immediately

Note: After clearing, the memory is still initialized. You don't need to call initialize() again unless you want to change dimension or precision.

18.9 Integration with Agents

GraphMemory is designed to work seamlessly with the Agent class. When memory is enabled on an agent, it automatically:

  • Queries relevant memories before each agent response using hybrid retrieval (3 recent + 5 semantic matches by default)
  • Injects formatted context into the agent's prompt (including metadata prefixes when present)
  • Optionally stores the full prompt/response after each think() when setAutoRememberOnThink(true) (default: true for generic agents, often false in Ralph Wiggum), tagged with metadata type: episodic, source: agent, and scope when a memory scope is active
  • Queries memory before each think() with minScore: 0.5, excludeType: episodic on the semantic path (recent episodic turns are still included via recentCount), and optional scope from setMemoryScope() or MALDA_CHAT_ID (Telegram sets chat:{id} per message)
  • Allows manual memory storage via agent.remember()
  • Supports explicit LLM tools via agent.addMemoryProgressTools()
var client = new OpenRouterClient();
var agent = new Agent("Assistant", "helper", "You help users.", client);

// Enable memory
agent.enableMemory();

// Agent can now remember facts
agent.remember("User prefers dark mode");

// Memory is automatically queried and injected into prompts
var response = agent.think("What are my preferences?");
// Agent will have access to "User prefers dark mode" in its context

// Access memory directly if needed
var memory = agent.getMemory();
if (memory != null) {
    var results = memory.query("preferences");
    // Process results...
}

Agent Memory Methods:

  • agent.enableMemory() - Enable memory with default settings
  • agent.enableMemory(dimension) - Enable memory with custom dimension
  • agent.enableMemory(dimension, precision) - Enable memory with custom settings
  • agent.useMemory(memory) - Use an existing GraphMemory instance (shared memory; see below)
  • agent.remember(fact) - Store a fact in agent's memory
  • agent.remember(fact, context) - Store a fact with context
  • agent.getMemory() - Get the GraphMemory instance (or null if not enabled)
  • agent.setAutoRememberOnThink(enabled) - Control whether think() auto-stores the full prompt and response (default: true)
  • agent.setMemoryScope(scope) - Pin memory reads/writes to a scope (e.g. chat:123); overrides MALDA_CHAT_ID when set. Use MALDA_MEMORY_SCOPE in assistant.malda for a custom default
  • agent.addMemoryProgressTools() - Register remember_progress and recall_progress tools (requires memory enabled first)

18.9.1 Progress memory tools

After addMemoryProgressTools(), the LLM can read and write progress notes intentionally during a turn:

  • remember_progress(note, type?, phase?) - Save a concise note (type: progress, decision, file, error)
  • recall_progress(query?, maxResults?, phase?) - Retrieve recent + semantically relevant notes (read-only; may run in parallel with other read-only tools)
  • When the agent has an active memory scope (setMemoryScope or MALDA_CHAT_ID), progress notes are saved and recalled within that scope; recall uses minScore: 0.5 and excludes episodic from the semantic path (same as agent think())
agent.enableMemory();
agent.addMemoryProgressTools();
// LLM can call remember_progress / recall_progress during tool rounds

18.10 Shared Memory

Multiple agents can share the same GraphMemory instance so they see each other's remembered facts. This is useful for multi-agent workflows, team assistants, or when agents run in different actors and need a common knowledge base.

Pattern: Create one GraphMemory, optionally load from disk, then attach it to each agent with useMemory(memory).

// Create a single memory (optionally load from disk)
var memory = new GraphMemory();
memory.initialize();
memory.load("shared_memory");   // optional: load previous state

// Create agents and attach the same memory
var agent1 = new Agent("A1", "role1", "instructions", client);
var agent2 = new CodingAgent("A2", "role2", "instructions", client);
agent1.useMemory(memory);
agent2.useMemory(memory);

// Both agents now share the same memory
agent1.think("Remember: user prefers dark mode");
agent2.think("What are the user's preferences?");  // can see the remembered fact

// Persist when done
memory.save("shared_memory");

Persistence: Use memory.load(path) and memory.save(path) to persist shared memory across sessions. All agents using that instance will see the same stored facts after load.

Thread safety: GraphMemory is thread-safe. When agents that use the same memory run in different actors (or threads), all operations (query, remember, save, load, etc.) are serialized per instance, so shared memory can be used safely from multiple actors.

18.11 Complete Example

// Create and initialize memory
var memory = new GraphMemory();
memory.initialize(384, "single");

// Store some facts
var node1 = memory.remember("My name is Alice");
var node2 = memory.remember("I work as a software engineer");
var node3 = memory.remember("I prefer dark mode", "UI preferences");
var node4 = memory.remember("I like Python and JavaScript", "programming languages");

// Query for relevant memories
var results = memory.query("What programming languages do I like?");
print("Found " + results.length + " relevant memories");
foreach (var result in results) {
    print("- " + result.fact);
}

// Find related nodes
var related = memory.findRelated(node1);
print("Found " + related.length + " related nodes");

// Add code elements
memory.addCodeElement("UserService.createUser", dict {
    "type": "function",
    "name": "createUser",
    "description": "Creates a new user"
});

// Analyze a source file
var count = memory.analyzeFile("src/UserService.malda");
print("Extracted " + count + " code elements");

// Save memory for later
memory.save("my_agent_memory");

// Later, load it back
var memory2 = new GraphMemory();
memory2.load("my_agent_memory");

// Query still works
var results2 = memory2.query("user creation");
print("Found " + results2.length + " results after loading");

18.12 Use Cases

GraphMemory is ideal for:

  • Long-Running Agents: Agents that need to remember context across multiple sessions
  • Codebase Understanding: Analyzing and understanding relationships in codebases
  • RAG Systems: Retrieval-Augmented Generation with graph-based relationship understanding
  • Knowledge Bases: Building semantic knowledge bases with relationship tracking
  • PRD-Driven Autonomous Loops: Ralph Wiggum (Examples/RalphWiggum/RalphWiggum.malda) persists structured iteration summaries and indexes modified files — see 17.18 Ralph Wiggum
  • Multi-Session Conversations: Maintaining context across conversation sessions
  • Document Analysis: Understanding relationships between documents and concepts

18.13 Technical Details

  • Vector Dimension: Default 384, configurable during initialization
  • Precision: "single" (4 bytes per element) or "double" (8 bytes per element)
  • Embedding: Uses embedBagOfWords() built-in function for text embeddings
  • Graph Type: Directed graph for relationship modeling
  • Search Algorithm: Vector similarity search + BFS graph traversal
  • Persistence Format: JSON for graph/metadata, binary for vector database
  • Thread Safety: All operations are synchronized per instance; safe to share one GraphMemory across multiple agents or actors
