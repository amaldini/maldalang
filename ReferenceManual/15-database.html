15. Database Support

MALDA includes native support for database operations with SQL Server, PostgreSQL, and SQLite. All database clients provide connection management, raw SQL queries with parameterization, query builder APIs, and transaction support.

15.1 SqlServerClient Class

The SqlServerClient class provides a SQL Server database client with full CRUD operations support.

Constructor

var db = new SqlServerClient();
// OR
var db = new SqlServerClient(connectionString);  // Optional connection string

Connection Management

  • connect(connectionString): Connect to SQL Server database
  • disconnect(): Close the database connection
  • isConnected (property): Check if currently connected

Raw SQL Queries

  • query(sql, params?) → array: Execute SELECT query and return array of result objects
  • queryOne(sql, params?) → object: Execute SELECT query and return single row (or null)
  • execute(sql, params?) → int: Execute INSERT/UPDATE/DELETE and return rows affected

Query Builder API

The query builder provides a fluent interface for building SQL queries:

  • select(...columns): Start a SELECT query (returns self for chaining)
  • from(table): Specify table name (returns self for chaining)
  • where(column, operator, value): Add WHERE condition (returns self for chaining)
  • where(column, value): Shorthand for where(column, "=", value)
  • query(): Execute the built query and return results

CRUD Operations

  • insert(table, values): Insert a new row (values is an object with column names as keys)
  • update(table, values): Update rows (requires where() conditions)
  • delete(table): Delete rows (requires where() conditions)

Transactions

  • beginTransaction(): Start a transaction
  • commit(): Commit the current transaction
  • rollback(): Rollback the current transaction

Parameterized Queries

SQL Server uses @paramName syntax for parameters. Parameters are passed as an object to prevent SQL injection:

var results = db.query("SELECT * FROM users WHERE age > @age", {age: 25});

Example

var db = new SqlServerClient();
db.connect("Server=localhost;Database=mydb;User Id=user;Password=pass;");

// Raw SQL with parameters
var users = db.query("SELECT * FROM users WHERE age > @age", {age: 25});

// Query builder
var results = db.select("name", "email")
                .from("users")
                .where("age", ">", 25)
                .query();

// Insert
db.insert("users", {name: "John", email: "john@example.com", age: 30});

// Update
db.update("users", {email: "newemail@example.com"})
  .where("id", "=", 1);

// Delete
db.delete("users")
  .where("id", "=", 1);

// Transactions
db.beginTransaction();
try {
    db.execute("INSERT INTO users (name) VALUES (@name)", {name: "Test"});
    db.commit();
} catch (e) {
    db.rollback();
}

db.disconnect();

15.2 PostgresClient Class

The PostgresClient class provides a PostgreSQL database client with the same interface as SqlServerClient.

Constructor

var db = new PostgresClient();
// OR
var db = new PostgresClient(connectionString);  // Optional connection string

Connection Management

Same as SqlServerClient: connect(), disconnect(), isConnected

Raw SQL Queries

Same interface as SqlServerClient: query(), queryOne(), execute()

Query Builder API

Same interface as SqlServerClient: select(), from(), where(), query()

CRUD Operations

Same interface as SqlServerClient: insert(), update(), delete()

Transactions

Same interface as SqlServerClient: beginTransaction(), commit(), rollback()

Parameterized Queries

PostgreSQL uses $1, $2, $3... syntax for parameters. Parameters are passed as an object:

var results = db.query("SELECT * FROM users WHERE age > $1", {$1: 25});

Example

var db = new PostgresClient();
db.connect("Host=localhost;Database=mydb;Username=user;Password=pass;");

// Raw SQL with parameters
var users = db.query("SELECT * FROM users WHERE age > $1", {$1: 25});

// Query builder (parameters handled automatically)
var results = db.select("name", "email")
                .from("users")
                .where("age", ">", 25)
                .query();

// Insert, Update, Delete work the same as SqlServerClient
db.insert("users", {name: "Jane", email: "jane@example.com", age: 30});

db.disconnect();

15.3 SqliteClient Class

The SqliteClient class provides a SQLite database client with the same interface as SqlServerClient.

Constructor

var db = new SqliteClient();
// OR
var db = new SqliteClient(connectionString);  // Optional connection string

Connection Management

Same as SqlServerClient: connect(), disconnect(), isConnected

Raw SQL Queries

Same interface as SqlServerClient: query(), queryOne(), execute()

Query Builder API

Same interface as SqlServerClient: select(), from(), where(), query()

CRUD Operations

Same interface as SqlServerClient: insert(), update(), delete()

Transactions

Same interface as SqlServerClient: beginTransaction(), commit(), rollback()

Parameterized Queries

SQLite uses @paramName syntax for parameters. Parameters are passed as an object:

var results = db.query("SELECT * FROM users WHERE age > @age", {age: 25});

Example

var db = new SqliteClient();
db.connect("Data Source=app.db;");

// Raw SQL with parameters
var users = db.query("SELECT * FROM users WHERE age > @age", {age: 25});

// Query builder
var results = db.select("name", "email")
                .from("users")
                .where("age", ">", 25)
                .query();

db.disconnect();

15.4 Key Differences

  • Parameter Syntax: SQL Server and SQLite use @paramName; PostgreSQL uses $1, $2, $3...
  • Connection Strings: Different formats (SQL Server: Server=...;Database=...; PostgreSQL: Host=...;Database=...; SQLite: Data Source=path/to/db.sqlite;)
  • Query Builder: Automatically handles parameter numbering for PostgreSQL

15.5 Security

All database clients use parameterized queries by default, preventing SQL injection attacks. Always use parameters instead of string concatenation when building queries.

⚠️ Important: Never concatenate user input directly into SQL queries. Always use parameterized queries to prevent SQL injection attacks.

15.6 Result Objects

Query results are returned as arrays of objects, where each object represents a row with column names as properties:

var users = db.query("SELECT name, email FROM users");
// users is an array: [{name: "John", email: "john@example.com"}, ...]

for (var i = 0; i < users.length; i++) {
    print(users[i].name + " - " + users[i].email);
}
