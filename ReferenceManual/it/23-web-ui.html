23. Componenti server Web UI

MALDA include il supporto nativo per UI renderizzata sul server usando componenti, fragment, aggiornamenti live e il runtime ui.*.

Parti da qui: Leggi 22. Panoramica Web UI per scegliere un modello UI. Questo capitolo copre due API lato server correlate ma distinte. Non passare stringhe HTML a ui.mount / ui.render e non trattare il valore di ritorno di @PAGE come un albero ui.* (IDE UI1002).
  • Frammenti HTML (23.2): component, @ACTION, @LIVE, componentFragment — pagine di form/liste che restituiscono HTML e SSE opzionale.
  • Alberi guidati dal server (23.3): ui.button(props, children?, key?), ui.mount / ui.render — patch incrementali ospitate da UIHost.

23.2 Componenti a frammenti HTML

Questa sezione è il modello a frammenti HTML: il server restituisce stringhe HTML (pagina intera o un fragment mirato). È additivo e retrocompatibile con le route @PAGE/@AIPAGE esistenti. Per gli alberi di nodi e ui.mount, salta a 23.3.

Modello mentale: renderizza sul server, muta tramite endpoint di action, opzionalmente fai push degli aggiornamenti su un canale live.

  • component Name(...) { ... } - funzione di ingresso del componente (zucchero sintattico per @COMPONENT())
  • @ACTION(path) - action POST per interazioni di form/pulsanti (in genere restituisce un fragment)
  • @LIVE(path) - endpoint live per client SSE (restituisci {"sse": true})
  • componentStateGet/Set/Object/Clear/Configure/Pin/Unpin - helper di stato lato server per chiave di componente (pin = vita del processo, esente da TTL/LRU)
  • componentFragment(targetId, html) - dice al client quale target DOM va sostituito
  • componentLiveEmit(channel, payload, eventType?) - trasmette eventi live ai client SSE connessi
  • onAgentProgress(handlerOrChannel) - sottoscrivi gli eventi del loop agente (round_start, tool_calls, tool_done, continue, done). Passa una funzione handler(event) (interprete) oppure una stringa di canale live così il progresso viene pubblicato con componentLiveEmit (adatto al transpile)
  • clearAgentProgress() - rimuove l'handler di progresso agente corrente o il canale live

23.2.1 Esempio server minimo

component ItemBoard() {
    var items = componentStateGet("board", "items", []);
    var list = "";
    var i = 0;
    while (i < items.length) {
        list = list + "<li>" + items[i].title + "</li>";
        i = i + 1;
    }
    return "<h1>Items</h1><div id='item-list'><ul>" + list + "</ul></div>";
}

@ACTION("/items/add")
function addItem(body) {
    var items = componentStateGet("board", "items", []);
    items.append({"title": body.title, "status": "open"});
    componentStateSet("board", "items", items);
    componentLiveEmit("items", {"count": items.length}, "item-added");
    return componentFragment("item-list", "<ul><li>" + body.title + "</li></ul>");
}

@LIVE("/items/live")
function itemsLive() {
    return {"sse": true};
}

23.2.2 Esempio minimo di integrazione nel browser

<form id="item-form">
  <input name="title" />
  <button type="submit">Add</button>
</form>
<div id="item-list"></div>
<script>
document.getElementById("item-form").addEventListener("submit", async (e) => {
  e.preventDefault();
  const fd = new FormData(e.target);
  const r = await fetch("/items/add", { method: "POST", body: fd });
  const html = await r.text();
  document.getElementById("item-list").innerHTML = html;
});

const es = new EventSource("/items/live");
es.onmessage = (evt) => console.log("live update", evt.data);
</script>

23.2.3 Contratto dei fragment

Quando un @ACTION restituisce componentFragment(targetId, html), la response HTTP include:

  • X-Malda-Fragment: true
  • X-Malda-Fragment-Target: <targetId>
  • Body che contiene l'HTML del fragment

L'helper AJAX built-in controlla questi header e aggiorna solo l'elemento target. Se gli header mancano, ricade sulla sostituzione dell'intera pagina.

23.2.4 Sottoscrizione canale LIVE

Usa il query parameter ?channel=... sugli endpoint LIVE per limitare gli eventi:

// Client subscribes only to item events
var es = new EventSource("/items/live?channel=items");

// Server emits only to channel "items"
componentLiveEmit("items", {"count": 8}, "item-added");

Si possono sottoscrivere più canali come valori separati da virgola, per esempio ?channel=items,alerts.

23.2.5 Envelope del protocollo UI server

L'host UI server usa envelope versionati per il trasporto mount/patch/event. I campi importanti includono:

  • version - stringa di versione del protocollo.
  • sequence - numero di sequenza monotono per l'ordinamento.
  • envelopeId - id usato per la correlazione ack/nack.
  • patches - operazioni di patch incrementali (ReplaceNode, SetProp, RemoveProp, InsertChild, RemoveChild).

I client dovrebbero confermare gli envelope elaborati e richiedere un resync quando rilevano buchi di sequenza.

Note di implementazione: Il kernel di runtime (UiNode, diff, sessioni), gli endpoint dell'host e le variabili d'ambiente sono documentati in docs/ui-framework.md. Questo capitolo resta concentrato sull'API del linguaggio.

23.2.6 Direzione API componenti V2

Il framework UI server ora include un set di componenti più ampio per form, navigazione, dati e feedback. Preferisci l'API ui.* di questo capitolo per i flussi UI server centrati sui componenti, e tieni @PAGE/@AIPAGE per i pattern di generazione HTML route-first.

I controlli avanzati includono ui.dataGrid (ordinamento/filtro/paginazione, selezione righe, eventi di virtualizzazione del viewport, hook drag/drop) e ui.treeView (nodi gerarchici, expand/collapse, selezione amichevole da tastiera, lazy loading opzionale). In entrambi i controlli, tieni lo stato di business lato server e usa stato transiente lato client per la reattività di scroll/viewport.

23.2.7 Guida alla migrazione: da @PAGE a component

  1. Tieni la route @PAGE esistente così com'è per compatibilità.
  2. Sposta la logica di rendering riutilizzabile in una nuova funzione component.
  3. Aggiungi endpoint @ACTION per le interazioni di form e pulsanti.
  4. Usa componentFragment(...) per restituire solo il blocco HTML interessato.
  5. Aggiungi @LIVE + componentLiveEmit(...) se la pagina ha bisogno di aggiornamenti push.

23.3 Riferimento API helper Web UI

Questa sezione è l'API del linguaggio sia per gli helper di fragment (componentFragment, template, HTML CRUD) sia per gli alberi ui.* guidati dal server (ui.mount, controlli, event loop). Gli helper di stato condivisi (componentState* / ui.state) valgono per entrambi.

23.3.1 Funzioni helper dei componenti server

  • renderTemplate(template, model?) - Sostituzione di token usando placeholder {{key}}.
  • componentFragment(targetId, html) - Restituisce un envelope di fragment standardizzato per aggiornamenti DOM parziali.
  • componentLiveEmit(channel, payload, eventType?) - Trasmette un evento live ai subscriber SSE.
var html = renderTemplate(
    "<h1>{{title}}</h1><p>{{count}} items</p>",
    {"title": "Items", "count": 4}
);

@ACTION("/items/add")
function addItem(body) {
    return componentFragment("item-list", "<ul><li>" + body.title + "</li></ul>");
}

componentLiveEmit("items", {"count": 7}, "item-added");

23.3.1.1 Workflow template nativo UI (UX trasparente)

Per le app più grandi, usa gli helper di template UI per tenere l'HTML in file esterni e la logica MALDA nel codice:

  • ui.template(source, model?, options?) - renderizza un file template (o sorgente inline) con interpolazione e helper di blocco.
  • ui.partial(source, model?) - renderizza un template fragment/partial.
  • ui.layout(source, slots, model?) - renderizza layout + slot nominati con placeholder {{slot:name}}.
  • ui.renderList(items, source, itemName?) - renderizza item ripetuti con un template item condiviso.
var base = "templates/";

var sidebar = ui.template(base + "sidebar.html", {
    "overviewClass": "nav-link active",
    "itemsClass": "nav-link"
});

var rowsHtml = ui.renderList(items, base + "item_row.html", "item");

var body = ui.partial(base + "items_body.html", {
    "rows": rowsHtml
});

return ui.layout(
    base + "layout.html",
    {
        "sidebar": sidebar,
        "pageBody": body,
        "pageScript": "initItems();"
    },
    {
        "pageTitle": "Items",
        "appCssPublicPath": "/static/app.css"
    }
);

Sintassi dei template:

  • {{key}} - interpolazione escaped (sicura di default)
  • {{{key}}} - interpolazione raw (usala di proposito)
  • {{#if condition}}...{{/if}} - rendering condizionale
  • {{#each items as item}}...{{/each}} - rendering di liste con alias
<ul>
{{#each items as item}}
  {{#if item.open}}
    <li>{{item.title}} - {{{item.badgeHtml}}}</li>
  {{/if}}
{{/each}}
</ul>

Compatibilità: passa {"compatRaw": true} a ui.template(..., ..., options) per preservare il comportamento raw legacy di {{key}} durante la migrazione.

Caching: i file template sono in cache di default. Passa {"cache": false} come terzo argomento a ui.template per il reload in fase di sviluppo.

Struttura consigliata: tieni i file template in una directory di progetto templates/ (per esempio templates/layout.html) e referenziali per path. I sample Web eseguibili stanno sotto Examples/Web/ (per esempio ui_form_workflow.malda e ui_controls_showcase_minimal.malda).

23.3.1.2 Pattern helper CRUD guidato da schema

Per le pagine CRUD che condividono lo stesso scheletro UI (filtri, dialog di add/edit, controlli lista), usa la pipeline schema built-in:

  • ui.crudModel(schema, sessionId?, queryParams?, lookups?) - costruisce il modello dei controlli consumato dai template CRUD condivisi.
  • ui.crudControls(schema, sessionId?, queryParams?, lookups?, options?) - costruisce il modello e renderizza l'HTML in un solo passo.
  • ui.crudSchema(schema, defaults?) - normalizza i default dello schema (path dei template, array di filtri, label) prima del render.

Comportamento di default: ui.crudControls risolve entity_controls.html sotto lo templateBasePath dello schema (default templates) quando non viene fornito un override di template.

  • Definisci uno schema solo-dati per entità: label, route, descrittori di filtro, path dei template, requisiti di lookup.
  • Usa ui.crudModel quando ti serve il controllo diretto sul rendering o sulla composizione dei template.
  • Usa ui.crudControls per il percorso end-to-end comune.
  • Tieni gli handler di pagina dell'entità concentrati su: parse della query, fetch di righe/lookup, una chiamata built-in, render del layout.
var schema = itemsCrudSchema; // data only
var sessionId = queryParams["session"] == null || queryParams["session"] == "" ? schema.sessionDefault : queryParams["session"];
var lookups = {"owners": allOwners(), "tags": listTags()};
var controlsHtml = ui.crudControls(schema, sessionId, queryParams, lookups);
var normalized = ui.crudSchema(schema, {
  "templateBasePath": "templates",
  "controlsTemplatePath": "templates/entity_controls.html"
});
var controlsHtml = ui.crudControls(normalized, sessionId, queryParams, lookups);

Override: passa {"templatePath": "...", "templateBasePath": "...", "cache": false} in ui.crudControls(..., options) quando ti serve un template dei controlli diverso, un base path diverso o un comportamento di cache diverso.

Nota di migrazione: se la tua app oggi normalizza a mano i campi dello schema CRUD, migra quella logica su ui.crudSchema per tenere i default dello schema coerenti tra le app.

23.3.1.3 Riferimento schema CRUD

L'oggetto passato a ui.crudSchema, ui.crudModel e ui.crudControls può contenere le proprietà seguenti. I valori vengono copiati nel modello usato per renderizzare il template dei controlli; le proprietà mancanti ricevono i default descritti.

Proprietà top-level dello schema

entitySingularLowerstringNome entità al singolare, es. "item". Usato da ui.crudSchema per derivare i default openAddLabel / openEditLabel quando omessi (default "item").
sessionDefaultstringId di sessione di default quando sessionId non viene passato a ui.crudControls / ui.crudModel. Default "default".

filterDefs — ogni elemento è un oggetto:

defaultValuestringValore di default quando il query param manca.

dialogLookupOptions — ogni elemento è un oggetto che lega un array di lookup a una chiave nel modello del dialog (es. per le opzioni dropdown nei form add/edit):

Risoluzione dei template: Quando chiami ui.crudControls(schema, ...), il template dei controlli può essere sovrascritto per chiamata via options.templatePath. Il path base per i template di dialog/lookup può essere sovrascritto via options.templateBasePath. I valori di schema templateBasePath e controlsTemplatePath (o controlsTemplate) vengono usati quando le options non forniscono override.

23.3.2 Helper di stato dei componenti server

  • componentStateGet(componentId, key, defaultValue?, scope?) — peek (il default non viene scritto)
  • componentStateSet(componentId, key, value, scope?)
  • componentStateObject(componentId, scope?)
  • componentStateClear(componentId?, scope?) (quando omesso, cancella tutto lo stato dei componenti)
  • componentStateConfigure(maxComponents, maxKeysPerComponent, ttlMs?)
  • componentStatePin(componentId, scope?) / componentStateUnpin(componentId, scope?) — pin esenta la voce nello scope da TTL e eviction LRU
var items = componentStateGet("board", "items", []);
items.append({"title": "Login issue"});
componentStateSet("board", "items", items);
print(componentStateObject("board"));
componentStateClear("board");

// Tenant/session scoping (optional)
componentStateSet("board", "count", 1, "tenantA");
componentStateSet("board", "count", 2, "tenantB");

// Safety policy tuning (defaults are conservative)
componentStateConfigure(512, 128, 1800000);

// Process-lifetime shared data (catalog, boot config): pin after write
componentStateSet("brain", "catalog", catalog, "ask-shared");
componentStatePin("brain", "ask-shared");

23.3.3 API di runtime e ciclo di vita della UI server

  • Ciclo di vita del render: ui.mount(rootNode, sessionId?), ui.render(rootNode, sessionId?)
  • Helper envelope: ui.mountEnvelope(rootNode, sessionId?, options?) per mount + snapshot + resync in una sola chiamata.
  • Sottoscrizioni di ciclo di vita: ui.onInit(componentId, sessionId?), ui.onPreRender(componentId, sessionId?), ui.onLoad(componentId, sessionId?), ui.onDispose(componentId, sessionId?), ui.onMount(componentId, sessionId?), ui.onUpdate(componentId, sessionId?), ui.onUnmount(componentId, sessionId?), ui.onError(componentId, sessionId?)
  • Pipeline eventi: ui.dispatchEvent(eventObj, sessionId?, sequence?), ui.pullEvent(sessionId?). sessionId è sempre il secondo argomento (stringa); sequence è il terzo opzionale (intero). Non passare sequence come secondo argomento.
  • Loop corretto: pullEvent → aggiorna lo stato → ricostruisci l'albero → ui.render. Saltare pull lascia la coda piena (IDE UI1001). Golden offline: Examples/Web/ui_event_loop.malda. Note sul motore: docs/ui-framework.md.
  • Stato: ui.state(componentId, key, defaultValue, scope?) (get-or-create — persiste il default), ui.getState(componentId, key, defaultValue?, scope?) (peek — non scrive), ui.setState(componentId, key, value, scope?), ui.pinState(componentId, scope?), ui.unpinState(componentId, scope?)
  • Invalidazione: ui.invalidate(channel, payload?)
  • Diagnostica/recovery: ui.snapshot(sessionId?), ui.resync(sessionId?)
  • Controlli di policy: ui.configure(settingName, value, sessionId?)
  • Helper di sessione: ui.sessionId(source, defaultSessionId?), ui.redirectWithSession(path, source, defaultSessionId?)

ui.configure supporta maxPatchCount, maxPayloadBytes, maxEventQueueDepth e sessionTtlMs.

var envelope = ui.mountEnvelope(rootNode, "app-session", {
  "maxPatchCount": 1024,
  "maxEventQueueDepth": 1024,
  "sessionTtlMs": 1800000
});
print(envelope.mount.type);
print(envelope.snapshot.version);
print(envelope.resync.type);
// source can be request object, body object, or query/body map containing "session"
var sessionId = ui.sessionId(req, "items-ui");
return ui.redirectWithSession("/web/items", body, "items-ui");

Gli eventi di ciclo di vita vengono emessi tramite ui.pullEvent() come payload type = "lifecycle". L'ordine tipico è:

  • ui.mount: onInit, poi onMount
  • ui.render per i componenti tracciati: onPreRender prima del diff
  • Componente esistente al render: onUpdate
  • Nuovo componente scoperto durante il render: onMount, poi onLoad
  • Componente rimosso: onUnmount, poi onDispose
  • Dispose/scadenza della sessione: i componenti tracciati emettono onDispose

Sottoscrivi chiamando l'helper corrispondente con l'id del componente (e la sessione opzionale). Quello registra l'hook; il payload arriva comunque su ui.pullEvent come type = "lifecycle". Showcase offline: Examples/Web/ui_counter_dashboard.malda.

ui.onMount("CounterRoot", sessionId);
ui.onUpdate("CounterRoot", sessionId);
ui.onUnmount("CounterRoot", sessionId);

23.3.3.1 Come viene ospitata una sessione ui.*

Un programma che chiama ui.mount o ui.mountEnvelope può avviare l'UIHost embedded (CLI e Desktop). Quell'host non è HttpServer / @PAGE — quelli restano in 24. HttpServer e generazione UI HTML.

  • Il client browser è malda-ui-client.js. La chiave di sessione è il sessionId che passi a ui.mount.
  • Endpoint tipici: WebSocket /ui/ws/{sessionId}, più il forwarding HTTP mount/patch sotto /ui/mount/{sessionId} e /ui/patch/{sessionId}.
  • Ambiente opzionale: MALDA_UI_AUTH_TOKEN (secret condiviso) e MALDA_UI_ALLOWED_ORIGIN (CORS).
  • Protocollo patch, campi envelope e interni dell'host: docs/ui-framework.md.

Per provare un albero senza browser, esegui il loop offline sotto (o Examples/Web/ui_event_loop.malda). Gli alberi generati dall'AI usano ui.generate — vedi 24.8.5.

23.3.3.2 Event loop (mount → pull → render)

Dopo ogni evento client: dispatchEvent (l'host accoda; gli esempi possono simulare) → pullEvent → aggiorna lo stato → ricostruisci l'albero → ui.render. Saltare pullEvent lascia la coda piena e la UI sembra bloccata (IDE UI1001).

var sessionId = "rm-event-loop";
var count = ui.state("LoopRoot", "count", 0, sessionId);

function buildView(value) {
    return ui.column(
        {"componentId": "LoopRoot"},
        [
            ui.text({"value": "count=" + string(value)}),
            ui.button({"label": "Inc", "onClick": "increment"})
        ]
    );
}

var mounted = ui.mount(buildView(count), sessionId);
print(mounted.type);

ui.dispatchEvent(
    {"type": "click", "targetPath": "/1/", "payload": {"action": "increment"}},
    sessionId
);

var evt = ui.pullEvent(sessionId);
if (evt != null) {
    count = count + 1;
    ui.setState("LoopRoot", "count", count, sessionId);
}

var patched = ui.render(buildView(count), sessionId);
print(patched.type);
print(count);

23.3.4 Catalogo dei controlli UI

I controlli UI seguono una firma coerente: ui.control(props, children?, key?).

  • Layout: ui.row, ui.column, ui.stack, ui.spacer, ui.panel
  • Display: ui.text, ui.heading, ui.image, ui.icon
  • Input: ui.button, ui.textField, ui.checkbox, ui.select, ui.slider, ui.datePicker
  • Form/navigazione: ui.form, ui.field, ui.textArea, ui.radioGroup, ui.switch, ui.tabs, ui.accordion, ui.breadcrumbs, ui.drawer
  • Dati/feedback: ui.list, ui.table, ui.alert, ui.progress, ui.modal, ui.dataGrid, ui.treeView, ui.paginator, ui.emptyState, ui.badge, ui.toast, ui.skeleton, ui.spinner, ui.errorBoundary
  • Composizione: ui.slot, ui.withSlot, ui.when, ui.choose, ui.each, ui.template, ui.partial, ui.layout, ui.renderList, ui.crudModel, ui.crudControls, ui.crudSchema, ui.mountEnvelope

ui.datePicker(props, children?, key?) renderizza un input nativo data (o data+ora). Props: name, value, defaultValue, placeholder, disabled, includeTime. Imposta includeTime a true per un picker data-e-ora. Usa stringhe data ISO per value/defaultValue: YYYY-MM-DD o YYYY-MM-DDTHH:mm. Eventi: onChange, onInput.

23.3.4.1 Stile dei controlli

Usa un approccio ibrido allo stile per i controlli Web UI: applica regole di design riutilizzabili con className e ritocchi per-istanza/dinamici con style.

  • className: stringa di classe CSS applicata direttamente all'elemento renderizzato.
  • style (stringa): testo CSS, per esempio "margin:8px; color:#1f2937;".
  • style (oggetto): mappa di proprietà, per esempio {"margin": "8px", "backgroundColor": "#f5f7fb"}.
  • Al re-render, l'ultimo valore di style sostituisce il valore di stile precedente per quel controllo.
var card = ui.panel({
    "className": "dashboard-card",
    "style": {"padding": "12px", "borderRadius": "10px", "backgroundColor": "#ffffff"}
}, [
    ui.text({"value": "Hybrid styling example"})
]);

23.3.5 Controlli dati avanzati

ui.dataGrid(props, children?, key?) supporta ordinamento/filtro/paginazione, selezione righe, virtualizzazione opzionale ed eventi di interazione drag/drop sulle righe.

L'ordinamento cliccando le intestazioni di colonna funziona con colonne sortable. Se è fornito onSort, la griglia emette eventi di sort per l'ordinamento lato server/gestito dallo stato; altrimenti il client applica l'ordinamento locale usando lo stato sort corrente.

  • Props core: columns, rows, rowKey, selectionMode, selectedKeys
  • Operazioni sui dati: sortable, sort, filter, page, pageSize, totalItems
  • Virtualizzazione: virtualize, rowHeight, overscan, height opzionale
  • Eventi: onRowClick, onSelectionChange, onSort, onFilter, onPageChange, onViewportChange, onDragStart, onDragOver, onDrop, onDragEnd

ui.treeView(props, children?, key?) offre navigazione gerarchica con expand/collapse, selezione amichevole da tastiera, lazy loading opzionale ed eventi di interazione drag/drop sui nodi.

  • Props core: nodes, nodeKey, expandedKeys, selectedKeys, selectionMode
  • Opzioni: showLines, lazy
  • Eventi: onNodeSelect, onNodeToggle, onNodeExpand, onNodeCollapse, onNodeActivate, onLoadChildren, onDragStart, onDragOver, onDrop, onDragEnd

Quando lazy è abilitato, espandere un nodo senza figli già caricati dovrebbe innescare il caricamento lato server (in genere tramite onLoadChildren) e poi un re-render con i figli restituiti.

var grid = ui.dataGrid({
    "columns": [{"key": "name", "title": "Name", "sortable": true}],
    "rows": [{"id": 1, "name": "Andrea"}],
    "rowKey": "id",
    "selectionMode": "single",
    "onSort": "sortUsers",
    "onSelectionChange": "selectUser",
    "onDrop": "moveUserRow",
    "virtualize": true,
    "rowHeight": 32,
    "overscan": 4
});

var tree = ui.treeView({
    "nodes": [{"id": "root", "label": "Root", "hasChildren": true, "childrenLoaded": false}],
    "lazy": true,
    "expandedKeys": ["root"],
    "onNodeToggle": "toggleNode",
    "onNodeSelect": "selectNode",
    "onLoadChildren": "loadTreeChildren",
    "onDrop": "moveTreeNode"
});

23.3.8 Pattern di gestione eventi

Collega le interazioni utente alle action server usando pattern coerenti:

  • onClick: click su pulsanti e trigger in stile link. Passa {"action": "handlerName"} nel payload quando fai dispatch.
  • onSubmit: invii di form. I dati del form vengono serializzati e inviati nel payload dell'evento.
  • onChange / onInput: cambi di valore dei campi. Usali per validazione in tempo reale o aggiornamenti con debounce.

I nomi delle action sono stringhe che il tuo event loop lato server mappa sul comportamento. Nei flussi UI server, elabora il payload dell'evento estratto, aggiorna lo stato e poi emetti fragment o fai re-render.

// Client: form submits; server returns fragment or JSON
ui.form({"onSubmit": "submitItem"}, [
    ui.textField({"name": "title", "onChange": "validateTitle"}),
    ui.button({"label": "Submit"})
])

// Server: process events from the queue
ui.dispatchEvent({"type": "submit", "targetPath": "/", "payload": {"action": "submitItem", "title": "Bug report"}}, sessionId);
var evt = ui.pullEvent(sessionId);
if (evt != null && evt.payload != null && evt.payload.action == "submitItem") {
    // validate/persist, then ui.setState(...) or return componentFragment(...)
}

Per i form basati su template, usa method="post" e action="/path/..." con l'helper AJAX built-in. Vedi 28. Sviluppo full-stack con MALDA per i pattern end-to-end.

23.3.9 Pattern di validazione form e rendering degli errori

Valida l'input sul server prima di persistere. Restituisci gli errori di validazione nella response e renderizzali accanto ai campi:

  • Usa required sugli input per i campi obbligatori; la validazione HTML5 gira prima del submit.
  • Lato server: valida negli handler @ACTION o @POST; restituisci componentFragment(...) con markup di errore inline.
  • Renderizza gli errori con ui.alert o ui.text con variant="error" / className="error".
@ACTION("/items/add")
function addItem(body) {
    var errors = [];
    if (body.title == null || body.title == "") {
        errors.append("Title is required");
    }
    if (body.email != null && indexOf(body.email, "@") < 0) {
        errors.append("Invalid email");
    }
    if (errors.length > 0) {
        var errHtml = "<ul class='error-list'>";
        var i = 0;
        while (i < errors.length) {
            errHtml = errHtml + "<li>" + errors[i] + "</li>";
            i = i + 1;
        }
        errHtml = errHtml + "</ul>";
        return componentFragment("item-form-errors", errHtml);
    }
    // persist and return success fragment
    return componentFragment("item-list", "<ul><li>" + body.title + "</li></ul>");
}

Sicurezza: Fai sempre escape del contenuto fornito dall'utente prima di incorporarlo in HTML. Usa {{key}} (interpolazione escaped) nei template, oppure un helper di escape attendibile per la concatenazione di stringhe raw. Non usare mai {{{key}}} per l'input utente.

23.3.10 Pattern di composizione

Costruisci UI riutilizzabile da pezzi più piccoli usando ui.slot, ui.withSlot, ui.when, ui.choose e ui.each:

  • ui.slot({"name": name}): nodo placeholder. Inietta dopo con ui.withSlot(parent, name, content).
  • ui.when(condition, thenNode, elseNode?): restituisce thenNode quando la condizione è vera; altrimenti elseNode, o null se omesso.
  • ui.choose(key, casesObject, defaultNode?): sceglie casesObject[string(key)], oppure defaultNode / null.
  • ui.each(items, propName?): restituisce un array di nodi ui.text, non un controllo lista. Ogni item è memorizzato in props[propName] (default "value"). Passa quell'array come figli di ui.column / ui.list.
var card = ui.panel({}, [ui.slot({"name": "title"}), ui.slot({"name": "body"})]);
var cardWithTitle = ui.withSlot(card, "title", ui.heading({"value": "Card Title"}));
var cardComplete = ui.withSlot(cardWithTitle, "body", ui.text({"value": "Body content"}));

var isOpen = true;
var status = "success";
var statusBadge = ui.when(isOpen, ui.badge({"value": "Open"}), ui.badge({"value": "Closed"}));
var alertByType = ui.choose(status, {"success": ui.alert({"variant": "success"}, [ui.text({"value": "OK"})])}, ui.alert({"variant": "info"}, [ui.text({"value": "Unknown"})]));
var labels = ui.each(["a", "b", "c"]);
var list = ui.column({}, labels);

23.3.11 Pattern di gestione dello stato

Gli handler di richiesta di HttpServer girano in un interprete isolato, quindi le variabili top-level non sono condivise tra le richieste. Usa lo store di stato dei componenti (via ui.* o componentState*) per i dati cross-request.

  • Peek vs get-or-create: ui.getState / componentStateGet restituiscono un default opzionale senza scrivere. ui.state persiste il default quando la chiave manca — non usare mai null o {} come default per chiavi critiche dopo un possibile miss TTL/LRU. IDE/LSP segnala UI1003 (Warning) per quei default letterali velenosi (anche il uiState piatto).
  • Pin per dati a vita del processo: dopo aver scritto catalogo/config condivisi, chiama ui.pinState(componentId, scope) (o componentStatePin) così TTL e eviction LRU saltano quella voce. Lascia la history per-conversazione senza pin.
  • ui.setState / componentStateSet: scrivi valori sia per flag UI di breve vita sia per dati server durevoli.

Regola pratica: fai peek con ui.getState quando leggi; usa ui.state solo quando vuoi di proposito get-or-create. Fai pin degli scope condivisi di brain/config; tieni gli scope di conversazione sotto TTL/LRU normale. Persisti gli invarianti di lungo periodo in file o in un database quando il processo può riavviarsi. Golden offline: Examples/Web/ui_state_lifecycle.malda — anche docs/ui-framework.md § State model.

// Peek (safe): missing key does not poison the store
var catalog = ui.getState("AskStore", "catalog", null, sharedScope);

// Get-or-create (OK for lists you always want initialized)
var items = ui.state("board", "items", [], convScope);
items.append({"title": "New", "status": "open"});
ui.setState("board", "items", items, convScope);

// Process-lifetime shared meta
ui.setState("AskStore", "session", meta, sharedScope);
ui.pinState("AskStore", sharedScope);

23.3.12 Pattern di routing e query param

Per i flussi master-detail e multi-pagina, usa i query parameter:

  • Pagina lista: /web/items?search=...&status=open&sort=id_desc
  • Pagina dettaglio: /web/items?id=42 oppure path param /web/items/42
  • Parsa req.query negli handler di pagina; passalo a ui.crudControls o ui.crudModel quando usi CRUD guidato da schema.
@PAGE("/web/items")
function itemsPage(req) {
    var queryParams = req.query == null ? {} : req.query;
    var sessionId = ui.sessionId(req, "items-ui");
    var schema = itemsCrudSchema;
    var lookups = {"owners": listOwners(), "tags": listTags()};
    var controlsHtml = ui.crudControls(schema, sessionId, queryParams, lookups);
    return appLayoutHtml("items", "Items", controlsHtml, "");
}

Per le chiamate REST API dal client, usa fetch o RestClient; vedi 27. Client REST Web per le chiamate HTTP lato server e 26. Server REST API per la progettazione API.

23.3.13 Note su errori e sicurezza

  • Escape: Usa {{key}} nei template per il contenuto fornito dall'utente (escaped di default). Usa {{{key}}} solo quando ti serve di proposito HTML raw (es. badge pre-renderizzati da fonti attendibili).
  • CSRF: Abilita enableCsrf(secret, cookieName?, headerName?) su HttpServer per le route che mutano. Il client deve inviare il token CSRF nell'header o nel campo del form.
  • Validazione: Valida tutto l'input della richiesta negli handler @ACTION e @POST; restituisci 400 con errori strutturati per i client API.

23.3.14 Linee guida sullo stile

Tieni layout e convenzioni CSS coerenti tra le pagine:

  • Usa className per classi semantiche: btn primary, nav-link, panel stack, muted.
  • Layout: stack per l'impilamento verticale, row per il flusso orizzontale; usa style per le colonne grid (grid-template-columns).
  • I template dell'app possono fornire layout, sidebar e controlli entità; referenzia il CSS condiviso tramite un helper di path pubblico.
var body = ui.layout(
    "templates/layout.html",
    {"sidebar": sidebarHtml, "pageBody": bodyHtml},
    {"pageTitle": "Items", "appCssPublicPath": "/static/app.css"}
);

23.3.15 Errori comuni e debugging

  • Fragment che non si aggiorna: Assicurati che gli header X-Malda-Fragment e X-Malda-Fragment-Target siano impostati; lo script client deve leggerli e aggiornare l'elemento target.
  • Stato perso tra le richieste: componentState* è scoped alla sessione; passa session in query/body oppure usa un cookie.
  • Handler evento che non scatta / UI bloccata dopo il dispatch: Svuota con ui.pullEvent, aggiorna lo stato, ricostruisci, poi ui.render. Il warning IDE UI1001 segnala dispatch→render senza pull. Vedi Examples/Web/ui_event_loop.malda.
  • @PAGE e alberi ui.* mescolati: Preferisci un modello per superficie; IDE UI1002 (Info) quando un file mescola entrambi. Non passare stringhe HTML a ui.mount / ui.render. Hub: 22. Panoramica Web UI.
  • Cache dei template: Passa {"cache": false} a ui.template per il reload in sviluppo.
  • Divergenza degli alberi: Usa ui.snapshot e ui.resync quando gli alberi client e server divergono.

23.4 Ciclo di vita dalla richiesta al render

  1. Il browser invia la richiesta a una route @PAGE, @AIPAGE, @ACTION o @GET/@POST.
  2. Il server risolve la route e costruisce HTML o un fragment di componente.
  3. Per i flussi a componenti, il server aggiorna lo stato (componentState* o ui.state/setState).
  4. Il server restituisce un documento completo, una response fragment oppure un envelope di patch del protocollo.
  5. Opzionale: i subscriber SSE ricevono messaggi componentLiveEmit/ui.invalidate per gli aggiornamenti live.

Per le parti route-first di questo ciclo di vita, inclusi HttpServer, @PAGE e HTML generato dall'AI, vedi HttpServer e generazione UI HTML.

23.5 Checklist di hardening in produzione

  • Abilita la protezione CSRF sulle route che mutano (enableCsrf) e verifica il flusso header/cookie da un capo all'altro.
  • Applica i rate limit (setRateLimit) e imposta una strategia di chiave esplicita per le API autenticate.
  • Valida l'input della richiesta (@Validate) e restituisci errori API standardizzati per i client JSON.
  • Imposta limiti ui.configure ragionevoli (maxPayloadBytes, maxEventQueueDepth, sessionTtlMs).
  • Usa stato gestito sul server per gli invarianti di business e tieni lo stato client transiente.
  • Aggiungi correlation ID nei log per il troubleshooting di route, action e SSE.

23.6 Test e risoluzione dei problemi

  • Usa getRoutes() per verificare la registrazione delle route per gli endpoint page/action/live.
  • Testa le response fragment asserendo gli header X-Malda-Fragment e X-Malda-Fragment-Target.
  • Per i problemi SSE, verifica i query parameter del canale e testa con un client EventSource minimo.
  • Quando gli alberi client divergono, ispeziona l'output di ui.snapshot e innesta ui.resync.
  • Per gli alberi di componenti server generati, rivedi il risultato di ui.mountEnvelope e rilancia ui.resync se un client resta indietro.
