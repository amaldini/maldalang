15. Supporto database

MALDA include il supporto nativo alle operazioni di database con SQL Server, PostgreSQL e SQLite. Tutti i client di database offrono gestione della connessione, query SQL raw con parametrizzazione, API di query builder e supporto alle transazioni.

15.1 Classe SqlServerClient

La classe SqlServerClient fornisce un client per database SQL Server con supporto completo alle operazioni CRUD.

Costruttore

var db = new SqlServerClient();
// OR
var db = new SqlServerClient(connectionString);  // Optional connection string

Gestione della connessione

  • connect(connectionString): Connette al database SQL Server
  • disconnect(): Chiude la connessione al database
  • isConnected (proprietà): Verifica se la connessione è attiva

Query SQL raw

  • query(sql, params?) → array: Esegue una query SELECT e restituisce un array di oggetti risultato
  • queryOne(sql, params?) → object: Esegue una query SELECT e restituisce una singola riga (oppure null)
  • execute(sql, params?) → int: Esegue INSERT/UPDATE/DELETE e restituisce le righe interessate

Query Builder API

Il query builder offre un'interfaccia fluente per costruire query SQL:

  • select(...columns): Avvia una query SELECT (restituisce self per il chaining)
  • from(table): Specifica il nome della tabella (restituisce self per il chaining)
  • where(column, operator, value): Aggiunge una condizione WHERE (restituisce self per il chaining)
  • where(column, value): Abbreviazione di where(column, "=", value)
  • query(): Esegue la query costruita e restituisce i risultati

Operazioni CRUD

  • insert(table, values): Inserisce una nuova riga (values è un oggetto con i nomi delle colonne come chiavi)
  • update(table, values): Aggiorna le righe (richiede condizioni where())
  • delete(table): Elimina le righe (richiede condizioni where())

Transazioni

  • beginTransaction(): Avvia una transazione
  • commit(): Esegue il commit della transazione corrente
  • rollback(): Esegue il rollback della transazione corrente

Query parametrizzate

SQL Server usa la sintassi @paramName per i parametri. I parametri si passano come oggetto per prevenire la SQL injection:

var results = db.query("SELECT * FROM users WHERE age > @age", {age: 25});

Esempio

var db = new SqlServerClient();
db.connect("Server=localhost;Database=mydb;User Id=user;Password=pass;");

// Raw SQL with parameters
var users = db.query("SELECT * FROM users WHERE age > @age", {age: 25});

// Query builder
var results = db.select("name", "email")
                .from("users")
                .where("age", ">", 25)
                .query();

// Insert
db.insert("users", {name: "John", email: "john@example.com", age: 30});

// Update
db.update("users", {email: "newemail@example.com"})
  .where("id", "=", 1);

// Delete
db.delete("users")
  .where("id", "=", 1);

// Transactions
db.beginTransaction();
try {
    db.execute("INSERT INTO users (name) VALUES (@name)", {name: "Test"});
    db.commit();
} catch (e) {
    db.rollback();
}

db.disconnect();

15.2 Classe PostgresClient

La classe PostgresClient fornisce un client per database PostgreSQL con la stessa interfaccia di SqlServerClient.

Costruttore

var db = new PostgresClient();
// OR
var db = new PostgresClient(connectionString);  // Optional connection string

Gestione della connessione

Come SqlServerClient: connect(), disconnect(), isConnected

Query SQL raw

Stessa interfaccia di SqlServerClient: query(), queryOne(), execute()

Query Builder API

Stessa interfaccia di SqlServerClient: select(), from(), where(), query()

Operazioni CRUD

Stessa interfaccia di SqlServerClient: insert(), update(), delete()

Transazioni

Stessa interfaccia di SqlServerClient: beginTransaction(), commit(), rollback()

Query parametrizzate

PostgreSQL usa la sintassi $1, $2, $3... per i parametri. I parametri si passano come oggetto:

var results = db.query("SELECT * FROM users WHERE age > $1", {$1: 25});

Esempio

var db = new PostgresClient();
db.connect("Host=localhost;Database=mydb;Username=user;Password=pass;");

// Raw SQL with parameters
var users = db.query("SELECT * FROM users WHERE age > $1", {$1: 25});

// Query builder (parameters handled automatically)
var results = db.select("name", "email")
                .from("users")
                .where("age", ">", 25)
                .query();

// Insert, Update, Delete work the same as SqlServerClient
db.insert("users", {name: "Jane", email: "jane@example.com", age: 30});

db.disconnect();

15.3 Classe SqliteClient

La classe SqliteClient fornisce un client per database SQLite con la stessa interfaccia di SqlServerClient.

Costruttore

var db = new SqliteClient();
// OR
var db = new SqliteClient(connectionString);  // Optional connection string

Gestione della connessione

Come SqlServerClient: connect(), disconnect(), isConnected

Query SQL raw

Stessa interfaccia di SqlServerClient: query(), queryOne(), execute()

Query Builder API

Stessa interfaccia di SqlServerClient: select(), from(), where(), query()

Operazioni CRUD

Stessa interfaccia di SqlServerClient: insert(), update(), delete()

Transazioni

Stessa interfaccia di SqlServerClient: beginTransaction(), commit(), rollback()

Query parametrizzate

SQLite usa la sintassi @paramName per i parametri. I parametri si passano come oggetto:

var results = db.query("SELECT * FROM users WHERE age > @age", {age: 25});

Esempio

var db = new SqliteClient();
db.connect("Data Source=app.db;");

// Raw SQL with parameters
var users = db.query("SELECT * FROM users WHERE age > @age", {age: 25});

// Query builder
var results = db.select("name", "email")
                .from("users")
                .where("age", ">", 25)
                .query();

db.disconnect();

15.4 Differenze principali

  • Sintassi dei parametri: SQL Server e SQLite usano @paramName; PostgreSQL usa $1, $2, $3...
  • Connection string: Formati diversi (SQL Server: Server=...;Database=...; PostgreSQL: Host=...;Database=...; SQLite: Data Source=path/to/db.sqlite;)
  • Query Builder: Gestisce automaticamente la numerazione dei parametri per PostgreSQL

15.5 Sicurezza

Tutti i client di database usano query parametrizzate di default, prevenendo gli attacchi di SQL injection. Usa sempre i parametri invece della concatenazione di stringhe quando costruisci le query.

⚠️ Importante: Non concatenare mai l'input dell'utente direttamente nelle query SQL. Usa sempre query parametrizzate per prevenire gli attacchi di SQL injection.

15.6 Oggetti risultato

I risultati delle query vengono restituiti come array di oggetti, in cui ogni oggetto rappresenta una riga con i nomi delle colonne come proprietà:

var users = db.query("SELECT name, email FROM users");
// users is an array: [{name: "John", email: "john@example.com"}, ...]

for (var i = 0; i < users.length; i++) {
    print(users[i].name + " - " + users[i].email);
}
