35.1 Appendice A: parole riservate

Le keyword sono definite in MaldaLang/Lexer.cs. fn e def non sono riservate; il parser le rifiuta come keyword di funzione. reply è una funzione built-in, non una parola riservata.

35.2 Appendice B: precedenza degli operatori

La tabella sotto rispecchia l'ordine di discesa del parser di riferimento (MaldaLang/Parser/Parser.cs), dalla precedenza più alta (lega più stretto) alla più bassa.

#LivelloOperatoriAssociatività
1PrimarioLetterali, identificatori, (…), letterali array / dict / graph / oggetto, comprehension, new, spawn, receive–
2PostfissoChiamata f(...), indice a[i], membro a.b, null-conditional a?.b e a?[i], postfisso ++ / --Sinistra
3Unario (prefisso)await, async, not (!), - unario, prefisso ++ / --Destra
4Moltiplicativo*, /, %Sinistra
5Additivo+, -Sinistra
6Confronto<, >, <=, >=Sinistra
7Uguaglianza==, !=Sinistra
8AND logicoand (&&)Sinistra
9OR logicoor (||)Sinistra
10Espressione matchmatch … { case … }–
11Coalescenza null??Destra
12Condizionale ternario? :Destra
13Pipe in avanti|>Sinistra
14Assegnamento=, +=, -=, *=, /=Destra
Due conseguenze da ricordare: |> lega più lasco del condizionale ternario, quindi a ? b : c |> f invia l'intero condizionale in pipe a f. E await è un operatore unario prefisso, quindi await a.b() attende il risultato della chiamata, mentre (await a).b() richiede parentesi esplicite.

35.3 Appendice C: riepilogo dei concetti object-oriented

Classi

  • Modello per creare oggetti
  • Contiene campi (dati) e metodi (comportamento)
  • Può avere costruttori per l'inizializzazione

Oggetti

  • Istanze di classi create con la keyword new
  • Ogni oggetto ha la propria copia dei campi di istanza
  • Condividono i metodi definiti nella classe

Ereditarietà

  • Le classi possono estendere altre classi con extends
  • Le classi figlie ereditano i membri public del genitore
  • Possono fare override dei metodi del genitore
  • Usa super per chiamare costruttore/metodi del genitore

Incapsulamento

  • I modificatori di accesso controllano la visibilità:
    • public: accessibile da qualsiasi punto
    • private: accessibile solo dentro la classe
  • I campi dovrebbero in genere essere private, accessibili tramite metodi public

Polimorfismo

  • L'override dei metodi permette alle classi figlie di fornire implementazioni diverse
  • Gli oggetti di tipo figlio possono essere trattati come tipo genitore

Membri statici

  • Appartengono alla classe, non alle istanze
  • Accessibili tramite il nome della classe
  • Condivisi tra tutte le istanze

35.5 Appendice E: baseline del contratto di deploy e osservabilità

Il comando malda deploy in questa baseline valida i contratti di configurazione ed esce senza avviare l'orchestrazione del deploy.

Contratti di input di default:

  • config/deploy.example.json
  • config/environments/prod.json (o --profile dev|test|prod)
  • config/observability.example.json

Aspettative minime validate:

  • I path di health/readiness sono presenti e collegati in modo coerente tra i contratti di deploy e di profilo ambiente.
  • La baseline di logging strutturato usa il formato JSON e include i campi core (timestamp, level, message, environment/profile, correlation opzionale).
  • Il collegamento dell'endpoint delle metriche è presente e coerente tra i contratti di profilo e di osservabilità.

35.6 Appendice F: profiling dei programmi MALDA

MALDA include un profiler built-in per le indagini sulle prestazioni. Può profilare esecuzioni interpretate ed eseguibili transpile e riporta gli hotspot in termini di built-in MALDA, funzioni e posizioni delle istruzioni.

Flag CLI supportati:

  • --profile - Abilita il profiling per l'esecuzione o per l'eseguibile compilato.
  • --profile-output <path> - Scrive il report su un path di file.
  • --profile-format text|json|both - Scegli testo leggibile, JSON strutturato, o entrambi.
  • --profile-periodic-seconds <N> - Durante l'esecuzione, riscrive i file di profilo ogni N secondi di wall-clock. Usa 0 (default) solo a fine esecuzione. Utile per i job lunghi, così un'esecuzione interrotta lascia comunque un report parziale recente su disco.

I report JSON includono un campo Partial: true per gli snapshot periodici, false per la scrittura finale in uscita. Gli snapshot periodici sovrascrivono lo stesso path di output; non inondano la console.

Esempi:

malda my-script.malda --profile
malda my-script.malda --profile --profile-output profile.json --profile-format json
malda my-script.malda --profile --profile-output profile.json --profile-format json --profile-periodic-seconds 60
malda compile my-script.malda --mode transpile -o my-script.exe --profile --profile-output profile.json --profile-format json

Il profiler al momento riporta:

  • BuiltIns - timing aggregato delle funzioni built-in
  • Functions - timing aggregato delle funzioni MALDA
  • Statements - timing aggregato delle istruzioni per posizione nel sorgente MALDA

Ogni voce del report include conteggio delle chiamate, tempo totale, tempo medio e self time. Il profiling a livello di espressione è volutamente escluso in questa prima versione per tenere l'overhead pratico.

35.7 Appendice G: pack opzionali

Il core MALDA tiene i pack di dominio fuori dal core pubblico. Il compilatore ha comunque hook di emit solo-stringa per i pack opzionali, così assembly distribuiti a parte possono innestarsi senza diventare ProjectReferences del core.

I pack verticali non sono inclusi in questo repository open-source. Se mantieni un pack di questo tipo, caricalo con loadNativeModule(...) e distribuisci le DLL accanto all'app; il core non registra automaticamente i global dei pack.
