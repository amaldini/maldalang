28. Backend UI JavaScript nel browser

MALDA supporta anche un modello UI ospitato nel browser in cui il sorgente MALDA viene transpile in JavaScript e gira con il runtime JS di MALDA. È distinto dai flussi server-side @PAGE, @AIPAGE e dai componenti server.

Parti da qui: Leggi 25. Panoramica Web UI per confrontare i modelli UI. Questo capitolo copre l'esecuzione MALDA lato browser, gli helper DOM, il template mode e l'API canvas/game. Per la UI renderizzata sul server, vedi Componenti server Web UI o HttpServer e generazione UI HTML.
Stop alla prima lettura. Il target è JavaScript nel browser, non l'harness degli snippet dell'interprete. Anteprima con malda play. File più piccolo: Examples/Web/js/hello_dom.malda. Parti da 25. Panoramica Web UI. Corso: Imparare MALDA — Dopo il percorso core.
Giochi nel browser: solo JS. Anteprima con malda play app.malda (vedi 2.0). Il canvas è 28.9, 3D e @shader() sono 28.10. Catalogo: 35.3. Showcase giocabile: 39 (solo schermo). Cartella: Examples/Games/.

28.2 Cosa offre questa modalità

  • API mode (.malda): scrivi MALDA che manipola il DOM con gli helper dom.*.
  • Template mode (.malda.html): scrivi template HTML-first con blocchi MALDA inline.
  • Copertura del linguaggio: il backend JavaScript supporta i sum type e il pattern matching match completo.
  • Libreria standard: ogni built-in puro math.* / str.* e gli helper di collezioni, JSON, codifica e conversione (sort, reverse, toCsv, toJSON / parseJSON, urlEncode, str.sha256, toIntOr, formatNumber, assert, …) girano con la semantica dell'interprete. Gli helper che richiedono una libreria host o si bloccano sui task (markdownToHtml, hashPassword, createJwt, race / firstOk / stream, AnsiConsole.*) falliscono in compilazione con JS0014. Le differenze rimaste (un solo tipo numerico, matematica trascendente, sequenze casuali, dialetto delle regex, cultura) sono elencate nella matrice delle capacità dei backend.
  • Supporto actor (locali): JS mode supporta actor locali con semantica di mailbox compatibile con il comportamento actor MALDA.
  • Supporto scene 3D: JavaScript mode include un wrapper curato three.* per scene 3D ospitate nel browser, più kernel @shader() compilati in GLSL (vedi 28.10).
  • Aspettativa di runtime: gli script generati richiedono malda-js-runtime.js prima che l'output MALDA venga eseguito.
  • UI lato client: i programmi ui.* girano nella pagina senza host (modalità locale, 26.8); il compilatore scrive malda-ui-client.js accanto all'output e lo carica prima del runtime.
  • Debug nell'IDE Desktop: F5 su programmi dom.* / game.* / three.* transpila in JavaScript, apre Web Preview e mappa i breakpoint dell'editor tramite source map. I file full-stack (@client() più @server() o una route) eseguono il debug dell'interprete host e di Web Preview insieme (vedi 2.6.6).

28.2.1 Decoratori target nell'output JS

Quando compili verso JavaScript, i decoratori target servono a tenere le preoccupazioni browser e server in un unico file sorgente:

  • Le dichiarazioni @client() e @javascript() sono incluse nell'output JavaScript.
  • Le dichiarazioni @server() e @csharp() sono escluse dall'output JavaScript.
  • Le dichiarazioni @shared() sono incluse sia nell'output C# sia in quello JavaScript.

I decoratori di route restano orientati al server. Una dichiarazione come @GET(...) è trattata come codice server e non viene emessa nell'output JavaScript.

28.3 Comandi di compile

# API mode (.malda source)
malda compile Examples/Web/js/hello_dom.malda --mode js -o Examples/Web/js/hello_dom.js

# Alias form (equivalent)
malda compile Examples/Web/js/counter.malda --target js -o Examples/Web/js/counter.js

# PWA output directory
malda compile Examples/Web/js/hello_dom.malda --target pwa -o dist/hello-dom

# Template mode (.malda.html source)
malda compile Examples/Web/js/hello_template.malda.html --mode js -o Examples/Web/js/hello_template.generated.js

--target js è un alias di --mode js. --target pwa è un alias di --mode pwa e produce una directory che contiene l'app shell, il runtime e il JavaScript transpile.

Il malda-js-runtime.js scritto accanto all'output tiene le parti game.* e three.* solo quando il programma le usa, così un programma che non le usa distribuisce un runtime grande circa la metà. I programmi compilati nella stessa cartella condividono il file, che tiene ogni parte usata da almeno uno di loro; la prima riga le elenca (// malda-js-runtime areas: game). Una chiamata a una parte tolta si ferma con malda-js-runtime.js was written without the 'game' area.

Il ciclo interno per i giochi canvas è malda play. Compila --mode js, scrive una pagina host e serve un URL locale così non devi scrivere HTML. Le modifiche al sorgente, all'index.html gemello e ad assets/ ricompilano e ricaricano il browser (--no-watch serve solo la prima compile). Il packaging per itch.io resta --mode pwa.

malda new game my-game
cd my-game
malda play app.malda

Canvas più API punteggi è malda new game --fullstack. Emette @client() / @GET / @POST e schema Score in un solo file. Compila con --mode fullstack; malda play rifiuta quelle sorgenti.

malda new game my-scores --fullstack
cd my-scores
malda compile app.malda --mode fullstack -o dist

28.3.1 Moduli ES (--mode esm)

--mode esm (alias --target esm) scrive un modulo ES, .mjs per default, accanto a malda-js-runtime.js e a un index.html che lo importa. Usalo per chiamare MALDA da JavaScript, o per dividere un'app in più moduli MALDA.

malda compile geometry.malda --mode esm -o web/geometry.mjs   # writes geometry.mjs + malda-js-runtime.js
malda compile scene.malda --mode esm -o web/scene.mjs         # same folder: one runtime for both
  • Export. Il modulo esporta funzioni, classi e variabili marcate export e i costruttori dei tipi esportati, la stessa regola di un import MALDA. Un file senza nessun export esporta ogni funzione, classe, actor, variabile e costruttore di variante del livello principale. Le dichiarazioni incorporate dai file .malda che importa non vengono riesportate.
  • Il codice di primo livello gira all'import. Le istruzioni del programma girano quando il modulo viene valutato (await main() in fondo al modulo), quindi chi importa vede le variabili esportate con i loro valori. Un errore fa fallire l'import.
  • Chiamare MALDA da JavaScript. Le funzioni esportate ricevono e restituiscono normali valori JavaScript. Una funzione che usa await restituisce una Promise.
  • Un solo runtime. Ogni modulo importa ./malda-js-runtime.js; i moduli compilati nella stessa cartella condividono una sola istanza del runtime. import js funziona allo stesso modo in un modulo.
  • L'output di default di --mode js non cambia: uno script classico che registra MaldaApp e gira quando la pagina host chiama MaldaApp.main().
// geometry.malda
export var UNIT = 10;
export function area(w, h) {
    return w * h * UNIT;
}
function helper() {          // not exported
    return 1;
}
import { area, UNIT } from "./web/geometry.mjs";
console.log(area(2, 3), UNIT);   // 60 10

28.3.2 Build di produzione (--minify) e dimensioni

Ogni build js, esm e pwa stampa la dimensione del programma, del runtime (con le aree che ha tenuto) e del client UI, grezza e gzip. --minify li minifica con esbuild quando lo trova (MALDA_ESBUILD, poi un node_modules/.bin sopra la cartella di lavoro o di output, poi il PATH); la source map del programma viene concatenata, quindi DevTools e la Desktop IDE puntano ancora alle righe .malda. Senza esbuild, --minify toglie commenti e indentazione dai file del runtime e lascia il programma com'è, e il report lo dice.

malda compile app.malda --mode js --minify -o dist/app.js
# JavaScript size (minified with esbuild):
#   app.js                  5.8 KB  (gzip 2.3 KB)
#   malda-js-runtime.js   158.5 KB  (gzip 46.4 KB)  areas: ui
#   malda-ui-client.js     59.6 KB  (gzip 19.0 KB)
#   total                 224.0 KB  (gzip 67.7 KB)

Un test di guardia tiene sotto una dimensione fissa il runtime scritto accanto a un programma senza aree opzionali (Compiler.CoreRuntimeBudgetCharacters); il nuovo codice di runtime che serve solo ad alcuni programmi va in un'area.

28.4 Ordine obbligatorio di caricamento degli script

La pagina host deve includere un contenitore come #app, poi caricare gli script in quest'ordine. Stesso file: Examples/Web/js/host.html.

  1. Qualsiasi dipendenza browser richiesta per il namespace scelto, per esempio three.js per three.*
  2. malda-js-runtime.js
  3. Lo script MALDA compilato
  4. La chiamata di bootstrap, come MaldaApp.main()
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>MALDA JS host</title>
</head>
<body>
  <div id="app"></div>
  <script src="../wwwroot/malda-js-runtime.js"></script>
  <script src="./counter.js"></script>
  <script>
    if (window.MaldaApp && typeof window.MaldaApp.main === "function") {
      window.MaldaApp.main();
    }
  </script>
</body>
</html>

println è un helper di console del backend JavaScript. L'interprete non ha println (usa io.print / print — vedi 12. Input/Output).

28.5 Helper DOM in API mode

Il runtime JavaScript espone helper browser sotto dom per la manipolazione diretta del DOM. Stesso programma: Examples/Web/js/counter.malda (compila con il comando in 28.3, poi apri la pagina host di 28.4).

  • dom.query(selector, root?)
  • dom.create(tagName)
  • dom.append(parent, child)
  • dom.clear(target)
  • dom.setText(target, text)
  • dom.html(target, markup)
  • dom.on(target, eventName, handler, options?)
  • dom.off(target, eventName, handler, options?), dom.queryAll(selector, root?), dom.remove(target)
  • dom.attr(target, name, value?) (legge, imposta, o rimuove con null), dom.addClass / dom.removeClass(target, ...names), dom.toggleClass(target, name, force?), dom.hasClass(target, name)
  • dom.style(target, name, value?) (valore calcolato, o imposta una proprietà) e dom.style(target, { name: value }); funzionano anche le proprietà personalizzate (--accent)
  • dom.focus / dom.blur(target), dom.rect(target) (x, y, width, height, …)
  • Puntatore e tastiera: dom.capturePointer / dom.releasePointer(target, pointerId), dom.keyCombo(event) ("Ctrl+Shift+K"); gli eventi di dom.on portano clientX, deltaY, ctrlKey … come valori JavaScript
  • dom.onResize(target, handler) chiama handler({ width, height }) a ogni cambio di dimensione e restituisce una funzione che lo ferma
  • Drag and drop: dom.dragData(event, value?) imposta il testo trascinato in dragstart e lo legge in drop; i file rilasciati passano da io.onFileDrop
  • Appunti: dom.copyText(text) e dom.readText(); il compilatore li attende, e il browser li consente solo dopo un'azione dell'utente
var panel = dom.query("#panel");
dom.addClass(panel, "busy");
dom.style(panel, { "width": "320px", "--accent": "#60a5fa" });
dom.attr(panel, "aria-busy", "true");
var stop = dom.onResize(panel, function (size) { println(size["width"]); });
dom.on(panel, "pointerdown", function (e) { dom.capturePointer(panel, e.pointerId); });
dom.on(panel, "keydown", function (e) {
    if (dom.keyCombo(e) == "Ctrl+C") {
        dom.copyText("copied");
    }
});
var root = dom.query("#app");

if (root == null) {
    println("No #app container found.");
} else {
    dom.clear(root);

    var count = 0;

    var title = dom.create("h1");
    dom.setText(title, "Counter example");
    dom.append(root, title);

    var valueLabel = dom.create("p");
    dom.append(root, valueLabel);

    function renderCount() {
        dom.setText(valueLabel, "Count: " + string(count));
    }

    var button = dom.create("button");
    dom.setText(button, "Increment");
    dom.append(root, button);

    function onIncrementClick() {
        count = count + 1;
        renderCount();
    }

    dom.on(button, "click", onIncrementClick);
    renderCount();
}

28.6 Sum type e pattern matching in JS mode

Puoi usare lo stesso modello di sum type e pattern matching in JavaScript backend mode come in modalità interpretata.

type Result = Ok(value) | Err(message);

function divide(a, b) {
    if (b == 0) return Err("divide by zero");
    return Ok(a / b);
}

var outcome = divide(10, 2);
var text = match outcome {
    case Ok(v): "ok: " + v;
    case Err(msg): "error: " + msg;
};
println(text);

Tutte le famiglie di pattern sono supportate in JS mode: letterali, identificatori, wildcard, payload delle variant, pattern di array con ...rest e pattern di oggetto nidificati.

28.7 Actor in JS mode

Il backend JavaScript include il supporto al runtime actor locale tramite mlRuntime.actors. Offre concorrenza actor lato browser o Node-local con semantica di mailbox allineata al comportamento actor MALDA.

  • Funzionalità supportate: actor, spawn, send in stile call, send con callback e timeout, reply(), receive(), self e routing di stop.
  • Il processing FIFO della mailbox per actor è preservato.
  • send target.stop(); passa dal comportamento di stop consapevole degli actor.

Confine: è solo supporto al runtime actor locale. La comunicazione trasparente diretta tra actor JS nel browser e actor lato server non è abilitata di default.

Archivio e file: io.store* conserva valori in IndexedDB tra i ricaricamenti, e io.openFile / io.saveFile / io.downloadFile / io.onFileDrop leggono e scrivono i file dell'utente. Vedi 12.11.

Fuori dal thread principale: un actor marcato @worker() gira in un Web Worker che il runtime avvia dal proprio sorgente (nessun file in più; una pagina aperta da file:// funziona), con i messaggi copiati via structured clone e buf.transfer per spostare i buffer. Vedi 18.13 Actor worker.

28.8 Sintassi del template mode

Il template mode usa file .malda.html. Usa {{ ... }} per l'interpolazione e {% ... %} per le istruzioni.

<div class="hello-template">
  <h1>Hello from template mode</h1>
  <p>User: {{ "Andrea" }}</p>
  {% var count = 2; %}
  <p>Count value: {{ count }}</p>
</div>

Vedi Examples/Web/js/host.html per una pagina statica minima che mostra il caricamento del runtime e il bootstrap dello script compilato.

28.9 API Game Canvas

Il backend JavaScript include un'API canvas/game nel browser sotto game.* per loop interattivi 2D semplici.

  • Disegno: game.clear(), game.fillRect(...), game.fillCircle(...), game.strokeCircle(...), game.drawText(...), game.measureText(text, font?), game.drawLine(...), game.strokeRect(...), game.setAlpha(a), game.setBlend(mode), game.getBlend(), game.setPixelated(enabled), game.getCanvasWidth(), game.getCanvasHeight()
  • Immagini e camera: game.loadImage(url), game.imageIsReady(handle), game.imageWidth(handle), game.imageHeight(handle), game.drawImage(...), game.drawImageRect(...), game.drawImageEx(handle, x, y, options?), game.drawTiles(handle, cells, tileW, tileH, options?), game.setCamera(x, y), game.followCamera(targetX, targetY, viewW, viewH, worldW, worldH, options?), game.getCameraX(), game.getCameraY(), game.setCameraZoom(z), game.getCameraZoom(), game.pushCamera(), game.popCamera(), game.screenToWorld(x, y), game.worldToScreen(x, y)
  • Buffer pixel / blit: game.createPixelBuffer(width?, height?), game.setPixel(x, y, r, g, b, a?), game.blitPixels(pixels?, destX?, destY?)
  • Collisione: game.overlapRect(x1, y1, w1, h1, x2, y2, w2, h2), game.overlapCircle(x1, y1, r1, x2, y2, r2), game.pointInRect(px, py, x, y, w, h), game.pointInCircle(px, py, x, y, r), game.sweepRect(x, y, w, h, dx, dy, ox, oy, ow, oh), game.sweepRects(x, y, w, h, dx, dy, obstacles), game.tileAt(cells, col, row, options?), game.sweepTiles(x, y, w, h, dx, dy, cells, tileW, tileH, options?)
  • Input: game.isKeyDown(key), game.wasKeyPressed(key), game.wasKeyReleased(key), game.getMouseX(), game.getMouseY(), game.getMouseWorldX(), game.getMouseWorldY(), game.isMouseDown(button?), game.wasMousePressed(button?), game.wasMouseReleased(button?), game.getTouches(), game.isGamepadConnected(index?), game.getGamepadAxis(index, axis, deadzone?), game.isGamepadButtonDown(index, button), game.wasGamepadButtonPressed(index, button), game.wasGamepadButtonReleased(index, button)
  • Audio: game.audioInit(), game.audioIsReady(), game.audioSetMasterVolume(v), game.audioPlayTone(...), game.audioPlayNoise(...), game.audioPlayPattern(pattern), game.audioStopPattern(), game.audioPlaySample(url, volume?, options?), game.audioStopSample(url?), game.audioLoadTrack(...), game.audioPlayTrack(), game.audioStopTrack(), game.audioSetTrackOptions(options), game.audioTrackIsReady(), game.audioGetTrackInfo(), game.audioCreateVoice(options?), game.audioSetVoice(voice, options), game.audioStopVoice(voice), game.audioSetListener(position, forward?, up?), game.audioStopAll()

Indicazioni su immagini e camera: game.loadImage restituisce subito un handle; la decode è asincrona. I draw sono no-op finché game.imageIsReady è true (i file mancanti restano unready, senza throw). game.imageWidth / game.imageHeight restituiscono la dimensione del bitmap, o 0 finché non è ready. game.drawImageEx(handle, x, y, options?) aggiunge source atlas, dimensione dest, origine, rotazione, flip e tint: { sx?, sy?, sw?, sh?, w?, h?, ox?, oy?, angle?, flipX?, flipY?, tint?, tintFill? }. x/y sono l'origine (default: angolo in alto a sinistra del dest). angle è in radianti; nel canvas Y+ va in basso quindi positivo è orario. flipX con ox = 0 disegna a sinistra di x — imposta ox a w / 2 per il facing in-place. tint è un colore CSS su una copia offscreen (omesso / vuoto → nessun tint). Il tint di default è multiply (il bianco è identità). tintFill: true sostituisce l'RGB e tiene l'alpha — il fill bianco è un hit-flash. game.setBlend(mode) / game.getBlend() impostano il composite del canvas per i draw successivi nel mondo: "alpha" (default), "add", "multiply", "screen" (sconosciuto → "alpha"). Il blend resta finché non lo cambi, come setAlpha; clear() composita sempre in alpha e non resetta la modalità; createCanvas torna a "alpha". Il blend non tocca setPixel / blitPixels. game.setCamera sottrae i draw successivi nel mondo (fillRect, drawImage, drawImageEx, linee, testo, strokeCircle). game.followCamera(targetX, targetY, viewW, viewH, worldW, worldH, options?) imposta il pan così il target sta in (screenX, screenY) e poi clamp della vista dentro (0, 0)–(worldW, worldH) (opzioni { screenX?, screenY?, snap? }; default: centro vista; snap: true fa floor del pan; non cambia lo zoom). game.setCameraZoom(z) poi scala quelle dimensioni mondo (default 1; clamp [0.05, 100]; non positivo → 1). La camera non sposta setPixel / blitPixels. game.measureText(text, font?) restituisce { width, height } in pixel del font non scalati (ignora pan/zoom — usalo per l'HUD dopo zoom 1). game.setPixelated(true) disattiva lo smoothing e imposta CSS image-rendering: pixelated; createCanvas lo resetta. getMouseX / getTouches restano in pixel del canvas; getMouseWorldX / getMouseWorldY / screenToWorld onorano pan e zoom. HUD: pushCamera, setCamera(0, 0), setCameraZoom(1), draw, popCamera (pop vuoto è no-op; lo stack memorizza pan e zoom). Vedi Examples/Games/game_sprite_smoke.malda.

Indicazioni sull'input: I fronti di tasti, mouse e gamepad sono snapshot all'inizio di update e sono false in render. Leggi wasKeyPressed / wasKeyReleased / wasGamepadButtonPressed / wasGamepadButtonReleased / wasMousePressed / wasMouseReleased solo in update (stessi nomi di isKeyDown; pulsante mouse di default 0). getTouches() restituisce { id, x, y } in pixel del canvas (vuoto se nessuno). Il primo tocco attivo continua ad aliasare il pulsante mouse 0, quindi un nuovo tocco fa anche da fronte di wasMousePressed(0). API Gamepad assente o pad scollegati: disconnected / asse 0. game.getGamepadAxis(index, axis, deadzone?) lascia la forma a due argomenti raw; deadzone opzionale (clamp [0, 1]) restituisce 0 se |v| ≤ deadzone, senza riscalatura radiale. game.stop() azzera tasti, fronti del mouse e fronti dei pulsanti. Vedi Examples/Games/game_input_smoke.malda.

Indicazioni sulla collisione: Gli helper di overlap sono inclusivi (i bordi che si toccano contano) e restituiscono false se larghezza, altezza o raggio sono ≤ 0. Sono funzioni pure: niente canvas, e non sottraggono setCamera. Non fermano un oggetto che a fine tick è già oltre un muro sottile. game.sweepRect(x, y, w, h, dx, dy, ox, oy, ow, oh) restituisce { hit, t, nx, ny, x, y } al primo contatto lungo il delta (miss: t 1 e la posa finale). game.sweepRects(x, y, w, h, dx, dy, obstacles) è lo stesso su un array di { x, y, w, h } (t più piccolo; in parità resta il primo; vuoto/non-array è miss). game.tileAt(cells, col, row, options?) restituisce l'id alle coordinate cella (righe nested o array piatto più columns; fuori range è out, default 0). game.drawTiles(handle, cells, tileW, tileH, options?) fa blit degli id non vuoti da un atlas (id 0 salta; indice atlas id - firstId, default 1; unready è no-op; la camera vale). game.sweepTiles(...) è sweepRect contro le celle solide (default: ogni id diverso da empty; solids opzionale). Nel canvas Y+ va in basso, quindi la normale del pavimento è ny = -1. Se si è già in penetrazione (overlap ad area positiva) t è 0 e la normale è la traslazione minima. Camminare su un pavimento in contatto mentre si fa sweep su X non è un hit. Non è un motore di fisica né Tiled/LDtk. Vedi Examples/Games/game_collision_smoke.malda e Examples/Games/game_tiles_smoke.malda.

Indicazioni sul loop: updateFn riceve dtMs. Scala il movimento per dtMs così l'animazione resta indipendente dal frame-rate. game.startFixed(updateFn, renderFn?, tickMs?) usa di default tickMs = 1000 / 60, accumula il tempo wall e chiama update(tickMs) zero o più volte per frame (max 5), poi render una volta. Non può girare insieme a game.start. Vedi Examples/Games/game_fixed_save_smoke.malda.

Indicazioni sul save: game.save / game.load / game.removeSave salvano JSON in localStorage scoped all'origine sotto il prefisso malda.game. (non file). Storage assente, quota o JSON corrotto: load restituisce null e save è no-op (senza throw).

Indicazioni sull'audio: chiama game.audioInit() dopo un gesto dell'utente per soddisfare le policy di autoplay del browser. game.audioPlaySample(url, volume?, options?) decodifica un WAV/OGG una volta per URL e lo mette in cache (volume default 1, clamp [0, 1]; opzioni { loop?: bool, pan?: number, playbackRate?: number }; pan clamp [-1, 1], default 0; playbackRate default 1, clamp [0.25, 4]). I one-shot possono sovrapporsi. game.audioStopSample(url?) ferma solo i sample — non ferma la track v1, il pattern o i toni. game.stop() non ferma implicitamente l'audio. I sample condividono il cap di 32 nodi con i toni. Vedi Examples/Games/game_audio_sample_smoke.malda.

Voci e suono 3D. Una voce è un suono che continua finché non lo fermi, come un motore, il vento o un ronzio. game.audioCreateVoice({ "wave": "sawtooth", "freq": 80, "cutoff": 900, "volume": 0.2 }) restituisce un handle. "wave" è sine, square, triangle, sawtooth (default) o noise. "cutoff" è un filtro passa-basso in Hz (default 20000, cioè nessun filtro), e "glide" è quanti secondi impiega un cambio ad assestarsi (default 0.03). game.audioSetVoice(voice, { "freq": 140, "volume": 0.3 }) scivola verso i nuovi valori, quindi puoi chiamarla a ogni update senza click. game.audioStopVoice(voice) sfuma la voce. Le voci non contano nel limite di 32 suoni brevi, e game.audioStopAll() ferma anche loro. Dai a una voce "position": [x, y, z] quando la crei, e suonerà attraverso un panner 3D invece del pan stereo. È a volume pieno entro "refDistance" (default 5), poi più bassa con la distanza, più in fretta quanto più alto è "rolloff" (default 1). 28.10 API scene three.js

Il backend JavaScript include un'API scene 3D curata sotto three.*. Usala quando vuoi una scena nel browser in MALDA senza scrivere chiamate THREE.* grezze. Il namespace è solo JavaScript mode; l'interprete e il transpile C# non eseguono questi helper. Le chiamate mappano su mlRuntime.three.* nello script generato.

Costruisci una scena in questo ordine: renderer, scene, camera, poi mesh e luci, poi three.start. three.createRenderer(width, height, mountSelector?) crea il canvas WebGL e lo appende all'elemento host (default "#app"). Chiamalo una volta, prima di three.render o three.start. Se ti serve una nuova dimensione o un secondo canvas, chiama prima three.stop() — non creare un altro renderer mentre il loop è in esecuzione.

  • Renderer e ciclo di vita: three.createRenderer, three.setClearColor, three.setRendererSize, three.setRenderScale(renderer, scale), three.setAutoRenderScale(renderer, targetFps?, minScale?, maxScale?), three.getRenderScale(), three.getStats(), three.showStats(visible?), three.start(updateFn, renderFn?), three.startFixed(updateFn, renderFn?, tickMs?), three.getFixedAlpha(), three.stop()
  • Scene graph: three.createScene(), three.createPerspectiveCamera(fovDeg, aspect, near, far), three.createOrthographicCamera(left, right, top, bottom, near, far), three.setCameraAspect(camera, aspect), three.createGroup(), three.createMesh(geometry, material), three.createInstancedMesh(geometry, material, count), three.setInstance(mesh, index, x, y, z, options?), three.setInstanceCount(mesh, count), three.add(parent, child), three.loadGLTF(url), three.modelIsReady(handle)
  • Primitive e lighting: three.createBoxGeometry(width, height, depth), three.createPlaneGeometry(width, height), three.createSphereGeometry(radius, widthSegments?, heightSegments?), three.createCylinderGeometry(radiusTop, radiusBottom?, height, radialSegments?), three.createTexture(url), three.createDataTexture(width, height, pixels, options?), three.updateDataTexture(handle, pixels), three.mandelbrotOrbit(real, imag, maxIter), three.createStandardMaterial(options), three.createShaderMaterial(options), three.setUniform(material, name, value), three.createDirectionalLight(color, intensity), three.createAmbientLight(color?, intensity?), three.setShadows(renderer, enabled), three.setShadow(object, cast, receive?), three.setLightShadow(light, options?), three.setFog(scene, color, near, far), three.setFogExp(scene, color, density)
  • Transform e input: three.setPosition(object, x, y, z), three.setRotation(object, x, y, z), three.setScale(object, x, y, z), three.lookAt(object, x, y, z, up?), three.render(renderer, scene, camera, options?), three.isKeyDown(key), three.wasKeyPressed(key), three.wasKeyReleased(key), three.getMouseX(), three.getMouseY(), three.isMouseDown(button?), three.wasMousePressed(button?), three.wasMouseReleased(button?), three.isGamepadConnected(index?), three.getGamepadAxis(index, axis, deadzone?), three.isGamepadButtonDown(index, button), three.wasGamepadButtonPressed(index, button), three.wasGamepadButtonReleased(index, button)

Passo fisso e fronti di input. three.startFixed(update, render?, tickMs?) è lo stesso loop di game.startFixed: update(dtMs) gira a un tick fisso (default 60 Hz, limitato a 1–1000 ms, al massimo 5 tick di recupero per frame), e render() gira una volta per animation frame. Così fisica e addestramento non dipendono dalla frequenza del display. In render, three.getFixedAlpha() restituisce quanto il frame si trova tra l'ultimo tick e il prossimo (da 0 a 1), utile per interpolare le posizioni. Le chiamate per pressioni, rilasci e gamepad hanno gli stessi nomi e le stesse regole delle gemelle game.*. Una pressione o un rilascio è visibile in esattamente un update, sia con three.start sia con three.startFixed, e le letture in render restituiscono false. Le letture del gamepad fuori da un loop interrogano direttamente il pad e non vedono fronti. three.stop() azzera tutto l'input.

Instancing, ombre e nebbia. three.createInstancedMesh(geometry, material, count) disegna fino a count copie di una mesh in una sola draw call. Ogni copia parte dall'origine. three.setInstance(mesh, index, x, y, z, options?) posiziona la copia index. Le opzioni sono "rotation" (un angolo su Y, oppure [rx, ry, rz]), "scale" (un numero oppure [sx, sy, sz]) e "color" (#rrggbb oppure [r, g, b] da 0 a 1, moltiplicato per il colore del materiale). Le copie che non ricevono mai un colore mantengono il colore del materiale. three.setInstanceCount(mesh, n) disegna solo le prime n copie. Le ombre richiedono tre interruttori. three.setShadows(renderer, true) accende la shadow map. three.setLightShadow(sun, { "extent": 20 }) fa proiettare ombre a una luce direzionale su un quadrato che arriva a extent unità mondo dal suo target, con near, far, mapSize (da 256 a 4096, default 1024), bias e normalBias opzionali. three.setShadow(object, cast, receive?) marca una mesh, un group o un modello glTF con tutti i figli; receive vale come cast se omesso. three.lookAt(light, x, y, z) orienta una luce direzionale o spot spostandone il target. Sposta la luce e il suo target insieme al giocatore per tenere un quadrato d'ombra piccolo e nitido attorno all'azione. three.setFog(scene, color, near, far) sfuma verso color tra due distanze, three.setFogExp(scene, color, density) sfuma in modo esponenziale, e un colore null toglie la nebbia. Usa il clear color come colore della nebbia, così l'orizzonte si fonde con il cielo. Accendere o spegnere ombre o nebbia ricostruisce i materiali della scena al three.render successivo. Gli shader material ignorano nebbia e ombre. Vedi Examples/Games/three_forest.malda.

Due passate: shader più mesh. Uno shader a schermo intero può disegnare la scena principale mentre mesh normali aggiungono il resto sopra. Fai scrivere al fragment shader gl_FragDepth per il primo impatto, con la proiezione di una camera prospettica con gli stessi near / far: (far + near) / (far - near) - 2 * far * near / ((far - near) * d), portato da −1..1 a 0..1, dove d è la distanza lungo la direzione di vista (scrivi 1.0 per il cielo). Poi chiama three.render(renderer, meshScene, perspectiveCamera, { "clear": false }): senza la cancellazione, le mesh mantengono colori e profondità dello shader e fanno il depth test contro di essi, così oggetti dello shader e mesh si coprono a vicenda correttamente. Orienta quella camera con three.lookAt(camera, x, y, z, [upX, upY, upZ]), usando il vettore up della camera dello shader, che funziona anche quando la camera guarda dritto in basso. three.createCylinderGeometry(radiusTop, radiusBottom, height, segments?) è un cilindro verticale centrato sull'origine (radiusTop 0 dà un cono). Examples/Games/three_shader_race_car_neural.malda fa il ray tracing di pista e auto, poi disegna così alberi, edifici e cartelli come mesh istanziate.

Scala di rendering e statistiche. Il buffer di disegno è la dimensione del renderer per devicePixelRatio (limitato a 2) per la scala di rendering. Il canvas mantiene la sua dimensione sulla pagina e il browser stira l'immagine. three.setRenderScale(renderer, 0.5) disegna un quarto dei pixel, il che conta soprattutto per gli shader per-pixel come un ray tracer. L'intervallo è da 0.25 a 2. three.setAutoRenderScale(renderer, 60, 0.5, 1) regola la scala da solo. Scende del 15% quando i frame al secondo restano sotto il 90% dell'obiettivo, e sale di 0.05 dopo 3 secondi all'obiettivo. Dopo una discesa la scala resta ferma per 4 secondi, e il primo secondo dopo l'avvio del loop o il ritorno della scheda viene ignorato. Tieni targetFps uguale o sotto la frequenza del display, altrimenti la scala può solo scendere. three.setRenderScale disattiva la modalità automatica. three.getStats() restituisce fps, frameMs, renderScale, autoScale, width / height del buffer di disegno, drawCalls e triangles, misurati su finestre di mezzo secondo. three.showStats(true) mostra gli stessi numeri nell'angolo del canvas. Aprire la pagina con #malda-stats nell'URL fa lo stesso senza codice. three.getMouseX() / getMouseY() sono in unità del renderer (la dimensione passata a createRenderer o setRendererSize), quindi né la scala di rendering né uno schermo HiDPI le cambiano.

Posizioni, scale e near/far della camera sono in unità mondo. Le rotazioni sono in radianti (un pavimento sul piano XZ è circa -1.5708 su X). Le opzioni di standard-material che il wrapper capisce includono "color" (#rrggbb), "roughness", "metalness" e "map" (un handle di three.createTexture). createTexture restituisce subito; la decode è asincrona e i file mancanti restano unready (senza throw). Il materiale lascia map unset finché l'handle è ready. three.createDataTexture(width, height, pixels, options?) è ready subito (RGBA; default float32, oppure "type": "byte"; nearest, senza mipmap). three.updateDataTexture(handle, pixels) riscrive quel buffer. three.mandelbrotOrbit(real, imag, maxIter) è BigInt solo JavaScript: passa stringhe decimali per C (i numeri MALDA sono IEEE double), cammina Zn+1 = Zn² + C a 256 bit frazionari e impacca (re, im, alive, 1) in una texture float a 1 riga. Le uniform dello shader-material unwrapano quegli handle per sampler2D. three.loadGLTF(url) restituisce un group che puoi add subito; i children compaiono quando three.modelIsReady(handle) è true (JSON .gltf o .glb; i fallimenti restano unready). Il runtime possiede il loader — le pagine host non aggiungono un quarto <script>. three.lookAt(object, x, y, z) richiede lookAt sull'oggetto three.js. I group parentano le mesh così puoi muovere un insieme con un solo setPosition / setRotation. I tasti di input usano gli stessi nomi dell'API canvas ("arrowleft", "arrowright", …).

Una prima scena con un cubo che gira, una key light e un loop su dtMs:

var width = 800;
var height = 500;
var aspect = width / height;

var renderer = three.createRenderer(width, height, "#app");
three.setClearColor(renderer, "#101722");
three.setRendererSize(renderer, width, height);

var scene = three.createScene();
var camera = three.createPerspectiveCamera(70, aspect, 0.1, 100.0);
three.setCameraAspect(camera, aspect);
three.setPosition(camera, 0, 0, 5);

var geometry = three.createBoxGeometry(1, 1, 1);
var material = three.createStandardMaterial({ "color": "#44aaff" });
var cube = three.createMesh(geometry, material);
three.add(scene, cube);

var light = three.createDirectionalLight("#ffffff", 1.1);
three.setPosition(light, 2, 3, 4);
three.add(scene, light);

var angle = 0.0;

function update(dtMs) {
    angle = angle + ((dtMs * 1.2) / 1000);
    three.setRotation(cube, angle, angle * 0.8, 0.0);
}

function render() {
    three.render(renderer, scene, camera);
}

three.start(update, render);

Indicazioni sul loop: updateFn riceve dtMs, come game.start. Scala rotazione e movimento per dtMs / 1000 così l'animazione resta indipendente dal frame-rate. Limita i valori enormi di dtMs dopo che un tab è stato in background se un singolo step saltrebbe troppo. Metti il disegno in renderFn (oppure omettilo e fai render alla fine di update).

28.10.1 Kernel shader (MALDA verso GLSL)

Quando game.setPixel sulla CPU è troppo lento, sposta il lavoro per-pixel sulla GPU. Questo è un sottoinsieme a compile-time JavaScript, non un quarto backend di esecuzione. Il MALDA host continua a possedere il loop three.* e gli aggiornamenti delle uniform. Il kernel possiede i raggi.

Marca le funzioni GPU con @shader() e raccoglile in una stringa GLSL con glsl.compile({ ... }). Quelle funzioni non vengono emesse come JavaScript o C#. Non chiamarle dal MALDA host. L'interprete e il transpile C# le saltano.

@shader()
function vertexMain() {
    vUv = uv;
    gl_Position = vec4(position.xy, 0.0, 1.0);
}

var vert = glsl.compile({
    varyings: ["vec2 vUv"],
    functions: ["vertexMain"],
    main: "vertexMain"
});

var material = three.createShaderMaterial({
    "vertexShader": vert,
    "fragmentShader": frag,
    "uniforms": { "uTime": 0 }
});
three.setUniform(material, "uTime", t);

glsl.compile accetta un solo object literal. Chiavi:

  • varyings / uniforms / consts — array di stringhe di dichiarazione GLSL, per esempio "vec3 uCamPos" o "float EPSILON = 0.0015"
  • functions — nomi delle funzioni @shader() in questo file da emettere, in ordine
  • main — quale di quelle funzioni diventa il void main() GLSL (usalo quando il nome MALDA è vertexMain / fragmentMain, perché un file non può dichiarare due funzioni MALDA chiamate main)
  • header — prefisso GLSL grezzo opzionale

Passa le stringhe risultanti a three.createShaderMaterial come "vertexShader" / "fragmentShader". I valori uniform dal MALDA host sono wrappati come { value }. Gli array di lunghezza 2/3/4 diventano Vector2 / Vector3 / Vector4. Le stringhe #rrggbb diventano Color. Gli handle texture da createTexture / createDataTexture / mandelbrotOrbit si unwrapano a THREE.Texture per sampler2D. Flag opzionali: "depthWrite": false, "depthTest": false, "transparent": true.

Per un pass a schermo intero usa three.createOrthographicCamera(-1, 1, 1, -1, 0, 1) e three.createPlaneGeometry(2, 2).

Array di uniform. Dichiarane uno con una dimensione, per esempio "vec3 uCars[CAR_COUNT]" insieme a consts: ["int CAR_COUNT = 8"], e indicizzalo nel kernel: return uCars[index];. glsl.compile scrive le const prima delle uniform, così una const può dare la dimensione a un array. createShaderMaterial legge le dichiarazioni uniform T nome[N] dalle stringhe shader, quindi three.setUniform(material, "uAngles", carH) riempie un float[8] invece di trasformare la lista in un Vector4. I tipi di elemento supportati sono float, int, bool, vec2/vec3/vec4 e ivec2/ivec3/ivec4. Gli array di vettori accettano una lista annidata ([[x, y, z], ...]) o piatta ([x, y, z, x, y, z, ...]). Le voci mancanti diventano zero, quelle in più vengono ignorate, e un array mai impostato parte da zero. Gli aggiornamenti scrivono nei valori esistenti, quindi chiamarlo a ogni frame non alloca nuovi vettori.

var frag = glsl.compile({
    uniforms: ["vec3 uCars[CAR_COUNT]", "float uAngles[CAR_COUNT]"],
    consts: ["int CAR_COUNT = 8"],
    functions: ["carPosition", "fragmentMain"],
    main: "fragmentMain"
});
three.setUniform(material, "uCars", [[0, 0, -5], [-3, 0, -8]]);
three.setUniform(material, "uAngles", carH);

Tipi nei kernel

vec2, vec3, vec4 e gli altri nomi vettore/matrice GLSL non sono tipi MALDA. Sono nomi GLSL memorizzati come type hint e copiati nello shader. Fuori da @shader(), var p: vec3 = ... è un Error di hint sconosciuto. I nomi che esistono già in entrambi i linguaggi — float, int, bool, void — restano hint MALDA ordinari.

Parametri e locali dello shader richiedono un type hint GLSL. I parametri che in GLSL si scriverebbero con out usano un hint di due parole: tHit: out float. Le uniform host restano array MALDA come [camX, camY, camZ], non valori vec3.

Array locali e cicli tipizzati. Un locale può essere un array di dimensione fissa: var stack: float[8]; emette float stack[8];. La dimensione è un intero letterale o il nome di una const (vec3[STACK]), e l'inizializzatore è facoltativo. Anche la variabile di un for accetta un hint: for (var i: int = 0; i < 64; i++) emette un for GLSL, così continue esegue comunque l'incremento. Gli hint di array sono una funzione GLSL: fuori da @shader(), var s: float[8]; è un errore di parsing. Sono ciò che serve a una piccola macchina a stack, per esempio un raymarcher che esegue una scena salvata come bytecode in una data texture (Examples/Games/three_sdf_interpreter.malda).

Sottoinsieme del linguaggio

Ammessi: if / else, while, for, return, aritmetica e confronti, and / or / not (emessi come && / || / !), swizzle di membro come position.xy, costruttori e builtin GLSL (vec3, dot, normalize, mix, clamp, …), e math.sqrt → GLSL sqrt (stesso per gli altri nomi math.* mappati).

Non ammessi nei kernel: actor, prompt, match, stringhe, foreach, await, classi e I/O MALDA. Un costrutto che l'emettitore GLSL non conosce fa fallire il compile JS con un errore GLSL transpile alla riga MALDA.

IDE

Poiché i kernel sono dichiarazioni function MALDA ordinarie, nel Desktop IDE e nell'LSP rename, trova riferimenti, highlight e outline si applicano agli identificatori nel kernel — a differenza del GLSL grezzo in una stringa """, che è un solo token. Rename continua a matchare il lessema in tutto il file (come nel resto di MALDA). Non riscrive le stringhe in glsl.compile (functions: ["hitSphere"], uniforms: ["vec3 uCamPos"], main: "fragmentMain"). Dopo aver rinominato un identificatore di kernel o di uniform, aggiorna quelle stringhe. I builtin GLSL (dot, gl_FragColor, nome di tipo vec3) non hanno una dichiarazione MALDA, quindi vai alla definizione non ha dove andare.

GLSL grezzo

Le stringhe GLSL tra triple quotes restano valide quando ti serve sintassi che il sottoinsieme non emette. Usa """, non $""", così le graffe restano letterali. Preferisci @shader() quando il kernel sta nel sottoinsieme, così rename e outline possono vederlo.

Shader composti a runtime

glsl.compile richiede opzioni letterali. Per costruire uno shader mentre il programma gira, prendi il GLSL delle funzioni @shader() come stringhe e uniscile a codice generato: glsl.source("a", "b", ...) è il GLSL di quelle funzioni in quell'ordine (prima le funzioni chiamate), e glsl.functions() è un dict dal nome di ogni funzione @shader() del file al suo GLSL. Entrambi si risolvono in compilazione; il risultato è una stringa normale per three.createShaderMaterial.

@shader()
function ripple(uv: vec2, time: float) -> float {
    return 0.5 + 0.25 * (sin(uv.x * 40.0 + time) + sin(uv.y * 31.0 - time));
}

var tint = "vec3(0.15, 0.35, 0.65)";         // chosen at runtime
var fragment = "varying vec2 vUv;\nuniform float uTime;\n" + glsl.source("ripple")
    + "void main() { gl_FragColor = vec4(" + tint + " * ripple(vUv, uTime), 0.7); }";

var library = glsl.functions();              // { "ripple": "float ripple(...) { ... }" }

28.10.2 Geometria da buffer, picking, controlli e render target

Queste chiamate coprono ciò che serve a strumenti di modellazione, CAD e dati sopra lo scene graph. Il WebGL2 grezzo resta a import js.

var positions = buf.float32(vertexCount * 3);   // computed by the program
var colors = buf.float32(vertexCount * 3);
var ground = three.createBufferGeometry({ "position": positions, "color": colors, "index": indices });
var terrain = three.createMesh(ground, three.createStandardMaterial({ "vertexColors": true }));

var controls = three.createOrbitControls(camera, { "target": [0, 0, 0], "maxPolarAngle": 1.5 });
three.fitToBounds(controls, terrain);

// in update(): a click that did not drag the view picks a face and paints it in place
if (three.wasMouseReleased(0) && !three.controlsMoved(controls)) {
    var hit = three.pick(camera, terrain, three.getMouseX(), three.getMouseY());
    if (hit != null) {
        for (var v in hit["vertices"]) {
            colors[v * 3] = 0.85;
            colors[v * 3 + 1] = 0.2;
            colors[v * 3 + 2] = 0.15;
        }
        three.updateGeometry(ground, "color");
    }
}

var minimap = three.createRenderTarget(256, 256);
three.renderToTarget(renderer, minimap, scene, topCamera);
var panel = three.createStandardMaterial({ "map": three.getTargetTexture(minimap) });
var pixel = three.readPixels(renderer, minimap, 128, 128, 1, 1);   // buf.bytes: r, g, b, a

Geometria da buffer. three.createBufferGeometry(attributes, options?) costruisce una geometria da buffer buf.* o array: "position" (obbligatorio), "normal" e "color" hanno 3 numeri per vertice, "uv" 2, ogni altro nome 1 salvo "itemSizes": { "name": n }, e "index" elenca tre numeri di vertice per triangolo. Un buffer buf.float32 diventa la memoria dell'attributo: scrivilo, poi chiama three.updateGeometry(geometry, name) e la mesh cambia sul posto. Gli altri buffer e gli array vengono copiati; three.updateGeometry(geometry, name, values) copia dentro valori nuovi (una lunghezza diversa sostituisce l'attributo, "index" prende un indice nuovo) e three.getAttribute(geometry, name) restituisce la memoria da scrivere. Le normali vengono calcolate quando non sono date ("computeNormals": false le salta) e ricalcolate dopo un aggiornamento delle posizioni; "dynamic": true marca i buffer per aggiornamenti frequenti. three.setDrawRange(geometry, start, count) ne disegna una parte. La stessa geometria si disegna come mesh (createMesh, con "vertexColors": true sul materiale per usare i colori), come linee con three.createLines(geometry, options?) (coppie di vertici, o una spezzata con "strip": true) o come punti con three.createPoints(geometry, options?) ("size", "sizeAttenuation"). Entrambe accettano "color", "vertexColors" (attivo di default quando c'è un buffer di colori) e "opacity".

Picking. three.pick(camera, target, x, y, options?) lancia un raggio dal pixel (x, y) del renderer, le coordinate che danno getMouseX / getMouseY, contro una scena, un oggetto o un array di oggetti (figli inclusi, oggetti nascosti esclusi). Restituisce il colpo più vicino come dict, oppure null: "object", "distance", "point" e "normal" ([x, y, z] nel mondo), "faceIndex" e "vertices" (i tre numeri di vertice della faccia) per le mesh, "index" per linee e punti, "instanceId" per le mesh instanziate, e "uv". Opzioni: "all": true (tutti i colpi, dal più vicino), "lineThreshold" / "pointThreshold" (quanto vicino deve passare il raggio, in unità mondo, default 0.1), "far", e "width" / "height" quando x e y non sono pixel del renderer. three.raycast(target, origin, direction, options?) fa lo stesso per un raggio nello spazio mondo. Per una scena grande, three.pickId(renderer, camera, scene, x, y) disegna la scena una volta in un target 1×1 con ogni mesh, linea e nuvola di punti (e ogni istanza di una mesh instanziata) in un proprio colore piatto e rilegge il pixel: il costo non cresce con il numero di oggetti, e restituisce { "object", "instanceId" } senza punto.

Controlli della camera. three.createOrbitControls(camera, options?) fa ruotare la camera attorno a un target: il trascinamento sinistro orbita, il destro, il centrale o shift + trascinamento spostano, la rotella e il pinch a due dita zoomano. Opzioni: "target", "minDistance" / "maxDistance", "minPolarAngle" / "maxPolarAngle" (radianti dalla verticale), "rotateSpeed", "panSpeed", "zoomSpeed", "enabled". Il programma può fare le stesse mosse: three.orbitControls(controls, azimuth, polar) in radianti, three.panControls(controls, dx, dy) in unità mondo, three.zoomControls(controls, factor) (2 dimezza la distanza), three.setControlsTarget(controls, x, y, z), e three.setControlsEnabled(controls, false) mentre un altro strumento usa il puntatore. three.controlsMoved(controls) è vero quando l'ultima pressione ha trascinato la vista, così un clic che chiude un trascinamento non viene preso per un pick. three.fitToBounds(controls or camera, object, margin?) inquadra un oggetto (margin 1.2 lascia il 20%). three.setProjection(controls, "orthographic" or "perspective") cambia camera tenendo della stessa dimensione ciò che sta al target, e restituisce la camera con cui disegnare (three.getControlsCamera(controls) la dà anche dopo). three.disposeControls(controls) toglie i listener.

Render target e lettura dei pixel. three.createRenderTarget(width, height, options?) crea un'immagine fuori schermo ("samples" per l'antialiasing, "depth": false, "linear": true per tenere i colori lineari invece dello sRGB dello schermo). three.renderToTarget(renderer, target, scene, camera) ci disegna dentro; three.getTargetTexture(target) fa da mappa a un materiale ("map") o alimenta una uniform sampler2D. three.readPixels(renderer, target, x?, y?, width?, height?) restituisce i byte RGBA come buffer buf.bytes, righe dall'alto come un'immagine; three.setTargetSize ridimensiona. three.screenshot(renderer, scene, camera, type?) disegna un frame e restituisce il canvas come data URL ("image/png" di default). Vedi Examples/Games/three_terrain.malda.

28.11 Interop JavaScript (import js)

import js lega moduli e globali JavaScript, così un programma MALDA può chiamare qualsiasi libreria: un pacchetto npm, un file locale .js / .mjs / .cjs, un modulo WASM tramite il suo glue JavaScript, o un'API del browser. Funziona solo in JavaScript: l'interprete e il transpile C# si fermano con un errore che rimanda a --mode js. In un sorgente full-stack appartiene alla metà client.

import js THREE = "three";                       // the module namespace
import js { Vector3, Mesh } from "three";       // named exports
import js geom = "./geom.wasm.js";             // a local module (here a WASM wrapper)
import js global document, window;             // properties of globalThis

var v = new THREE.Vector3(1, 2, 3);              // new accepts a dotted path
v.normalize();
var lib = await geom.init();                     // await a JavaScript Promise
var button = document.createElement("button");
button.addEventListener("click", function (e) { io.print(e.clientX); });
document.body.append(button);

28.11.1 Cosa lega ciascuna forma

  • import js NOME = "modulo"; lega il namespace del modulo. Il module.exports di un modulo CommonJS è NOME.default.
  • import js { a, b } from "modulo"; lega export con nome. Un nome che il modulo non esporta ferma il programma con import js "modulo" has no export 'a'. Gli export CommonJS che Node non riesce a elencare staticamente vengono letti da module.exports.
  • import js global a, b; legge globalThis.a, globalThis.b al caricamento del programma. Un globale mancante vale null.
  • js e global sono parole contestuali, non riservate: import js; resta l'import di un pacchetto, e una variabile può chiamarsi js. Gli import stanno solo al livello principale, come ogni import.

28.11.2 Caricamento e specificatori di modulo

  • I moduli si caricano con import() JavaScript scritto nel file generato, quindi uno specificatore relativo ("./geom.mjs") si risolve rispetto al file .js compilato, in Node e nel browser. Tieni il modulo accanto all'output, o compila accanto al modulo.
  • Il caricamento parte quando lo script viene caricato; main() attende tutti i moduli prima della prima istruzione. Un programma con moduli ha sempre un main() async. Un modulo che non si carica ferma main() con import js "modulo" failed: ….
  • Gli specificatori senza percorso ("three") si risolvono da node_modules in Node. Nel browser servono una import map o un URL completo ("https://…/three.module.js").
  • Il WASM si carica tramite il modulo JavaScript generato dalla sua toolchain (Emscripten, wasm-bindgen): importa quel modulo e chiama la sua funzione di init.
  • Lo stesso modulo importato da più file .malda si carica una volta sola. Un nome legato a due moduli o export diversi è un errore di compilazione.

28.11.3 Valori attraverso il confine

  • Array e dizionari MALDA sono array e oggetti JavaScript, quindi passano a JavaScript e tornano senza cambiare. null e undefined valgono entrambi null.
  • Una funzione o una lambda MALDA passata a JavaScript è una normale funzione JavaScript. Una funzione che usa await restituisce una Promise a chi la chiama da JavaScript.
  • await funziona su qualsiasi Promise JavaScript. Una Promise rifiutata, o un errore lanciato da JavaScript, è un errore MALDA: catch (e) ne riceve il messaggio.
  • Le chiamate su una catena che parte da un nome importato (document.body.append(x)) vengono emesse come JavaScript puro. Su qualsiasi altro valore, un metodo definito dall'oggetto JavaScript vince sul metodo MALDA omonimo: vec.set(1, 2) o list.append(x) su un oggetto JavaScript chiamano il metodo dell'oggetto.
  • == fra due oggetti JavaScript è l'identità. La verità resta quella di MALDA: 0 e "" restituiti da JavaScript sono veri; confronta in modo esplicito.
  • Nomi che un binding non può avere: le parole riservate di JavaScript (default, new, …) e i nomi propri del codice generato (mlRuntime, main, MaldaApp, __malda…). Importa il modulo come namespace e leggi il membro.

28.11.4 Test su JavaScript

malda test --target js compila ogni file di test in JavaScript e lo esegue in Node (imposta MALDA_NODE_PATH se node non è nel PATH). Durante l'esecuzione il programma compilato viene scritto accanto al file di test, così gli specificatori relativi di import js e node_modules si risolvono come per il programma compilato. Un assert o un throw che fallisce riporta il messaggio e la riga .malda tramite la source map. I test property girano solo sull'interprete.

malda test tests/ --target js

28.12 Errori comuni e indicazioni

  • Non modificare direttamente il JavaScript generato quando esiste un sorgente .malda corrispondente. Cambia il file MALDA e ricompila.
  • Carica malda-js-runtime.js prima dello script compilato, altrimenti l'app generata fallisce a runtime.
  • Un programma che usa ui.* richiede anche malda-ui-client.js, caricato prima del runtime con data-ui-mode="local" (lo fa l'index.html generato). Copia l'intera cartella di output, non solo il .js.
  • Carica Examples/Web/wwwroot/vendor/three.min.js prima di malda-js-runtime.js quando usi il namespace three.*.
  • three.* è JavaScript mode con un host browser. Chiama three.createRenderer prima di three.start o three.render. Non creare un secondo renderer mentre il loop è in esecuzione; prima three.stop().
  • Le rotazioni sono in radianti. Dopo un cambio di viewport, chiama sia three.setRendererSize sia three.setCameraAspect.
  • Tieni le preoccupazioni solo-browser in JS mode e quelle solo-server in @PAGE/@AIPAGE o nei componenti server.
  • Non combinare @client() con decoratori di route come @GET o @PAGE; è una combinazione di target non valida.
  • Usa @shared() solo per logica sicura in entrambi i runtime; tieni filesystem/database/API server e API solo-browser fuori dalle dichiarazioni shared.
  • Crea il canvas prima di disegnare o di avviare un game loop.
  • Usa malda new game e malda play app.malda invece di scrivere un file HTML host. malda play serve .malda-play/, non l'albero sorgente. Il packaging resta --mode pwa. Canvas più punteggi è malda new game --fullstack poi malda compile --mode fullstack; malda play rifiuta quelle sorgenti.
  • F5 dell'interprete non può fare debug di programmi dom.* / game.* / three.*. Usa F5 dell'IDE Desktop (Web Preview) oppure i DevTools del browser sul .js + .map compilato.
  • Usa API mode quando vuoi il controllo DOM completo e template mode quando la pagina è soprattutto HTML con poca logica MALDA.
  • Le funzioni @shader() sono kernel GLSL, non chiamabili dall'host. Compilale con glsl.compile e passa la stringa a three.createShaderMaterial.
  • Rename Symbol aggiorna gli identificatori MALDA, non i nomi stringa dentro glsl.compile({ ... }). Tieni quelle liste allineate.
  • Non usare vec3 / vec2 come tipi MALDA fuori da @shader(). Le uniform host sono array come [x, y, z].
  • three.mandelbrotOrbit è BigInt JavaScript, non l'interprete. Passa stringhe decimali per il centro; i numeri MALDA sono IEEE double e arrotondano un C profondo.
  • I numeri seguono JavaScript in due casi in cui interprete e transpile C# concordano tra loro: 1 == 1.0 è true in JS e false altrove (un intero non è mai uguale a un float); NaN == NaN è false in JS e true altrove. Per codice portabile confronta i float con una tolleranza o converti entrambi i lati. Divisione per zero, letture di array fuori range e scritture oltre la fine di un array si comportano come sull'interprete (un errore, un errore, riempimento con null). Uguale su tutti i backend: 0, "" e [] sono veri, e il terzo argomento di str.substring(s, inizio, lunghezza) è un conteggio, non un indice di fine, e math.round usa l'arrotondamento bancario (half to even, math.round(2.5) vale 2).
