33. Property testing

Una property è un invariante: una funzione che deve restituire true per molti input generati a caso. MALDA pesca quegli input da un seed, così lo stesso seed ripete le stesse prove. Usala quando pochi casi scritti a mano perderebbero un bordo (interi intorno a zero, stringhe vuote, liste corte). I flag CLI di malda test sono riassunti in 2. Strumenti e toolchain; questo capitolo spiega il costrutto del linguaggio.

33.1 Una property che passa

Dichiara una property come una funzione. Il corpo deve restituire un boolean. Stesso file: Examples/Testing/property_core_identity.malda.

property intIdentity(x) {
    return (x + 0) == x;
}

property boolInvolution(isFlag) {
    return (!(!isFlag)) == isFlag;
}

Eseguila con un seed fisso così un fallimento di domani è lo stesso di oggi:

malda test Examples/Testing/property_core_identity.malda --iterations 80 --seed 1337

Puoi anche invocare una property dichiarata da MALDA ordinario con runProperty(name, iterations?, seed?):

property stableIdentity(x) {
    return (x + 0) == x;
}

var result = runProperty("stableIdentity", 40, 1337);
print("Passed: " + string(result.passed));

runProperty(...) restituisce un oggetto con propertyName, passed, iterations, seed e, in caso di fallimento, failedTrial, error, counterexample, shrunkCounterexample.

33.2 Come vengono generati gli argomenti

MALDA non prende tipi di generatore espliciti. Sceglie il generatore dal nome del parametro (senza distinzione di maiuscole):

Nome del parametroValori generati
inizia con is / has, contiene flag, o finisce con boolboolean
contiene name o text, o finisce con stringstringhe (fino a 16 caratteri)
finisce con list, items o array, oppure è esattamente xsarray di interi
contiene anyun misto di int, bool, string e array corti di int
qualsiasi altro nome (incluso x)interi da -100 a 100

Per questo boolInvolution(isFlag) riceve boolean e intIdentity(x) riceve interi. Rinomina il parametro se il generatore è sbagliato; non esiste la sintassi property foo(x: string).

33.3 Una property che fallisce, shrinking e regressioni

Quando una prova restituisce false (o lancia), MALDA registra gli argomenti come controesempio, poi li riduce (shrinking): interi più vicini a zero, stringhe e liste più corte, finché il fallimento è il più piccolo che riesce a ottenere. Il payload ridotto è quello che vuoi nel file di regressione. Stesso file: Examples/Testing/property_failure_to_regression.malda.

property alwaysFails(x) {
    return x == (x + 1);
}

var result = runProperty("alwaysFails", 20, 1337);
print("Passed: " + string(result.passed));
# Observe the failure (same seed = same trials)
malda test Examples/Testing/property_failure_to_regression.malda --iterations 40 --seed 1337

# Write a deterministic .spec.malda repro from the shrunk counterexample
malda test Examples/Testing/property_failure_to_regression.malda --iterations 40 --seed 1337 --write-regression

# Optional output directory (default: tests/regressions)
malda test ./tests --write-regression --regression-dir ./artifacts/regressions

# CI JSON for the Desktop IDE "Create Regression" action
malda test ./tests --format ci --iterations 100 --seed 1337

MALDA stampa ogni path generato come Generated regression: .... L'azione Desktop Create Regression tratta i path CI come non attendibili: vengono sanitizzati e limitati al workspace prima di scrivere file. Il JSON CI include shrunkCounterexample, canGenerateRegression e recommendedRegressionPath.

Non “aggiustare” una property che fallisce cambiando il seed finché passa. Correggi il codice o l'invariante; tieni il seed così il vecchio controesempio si riproduce ancora.

33.4 Modello di capability

Le property che servono una funzionalità di runtime (actor, I/O su file, workflow) la dichiarano. Un backend che non può fornire la capability è non applicabile, non un fallimento. Stessa idea: Examples/Testing/property_js_capability_skip.malda.

@requires("core", "actors")
@targets("interpreter", "csharp", "js")
property actorSafetyInvariant(x) {
    return x == x;
}
  • @requires(...): tag di capability di cui la property ha bisogno
  • @targets(...): backend in cui è attesa

Tag @requires supportati:

  • Interprete: core, file-io, actors, workflows, dotnet-interop, host-interop
  • CSharp: core, file-io, actors, workflows, dotnet-interop, host-interop
  • JS: core, web-dom, game-canvas

La matrice di capability è la fonte di verità per l'idoneità dei backend tra interpreter, csharp e js.

33.5 Limitazioni JavaScript e semantica di skip

La parità del backend JavaScript è condizionata dalle capability. Se una property richiede capability JS non supportate, MALDA riporta JS come non applicabile con un motivo. Questo non fa fallire la parità dei backend che hanno girato.

Per le property idonee a JS in cui un harness JS delle property non è ancora abilitato, MALDA riporta JS come skipped con un motivo esplicito in stile TODO, invece di far fallire la parità.
