23. Agentic Runs

This chapter is the language surface for verifying and bounding agent programs: eval suites, LLM cassettes, the run journal, cancellation scopes, declared conversation context, a file-level capability policy, typed AgentError, streaming, grounded sinks, and the check/fix loop. Interpreter and C# transpile agree on the offline examples. JavaScript is host-only (n/a).

suite, context, policy, and within are contextual words, not reserved keywords. var context = 1; still parses. case is already a keyword (reused for suite cases vs match). expect and stream are builtins. CLI flags for these commands are summarized in 2. Tools & Tooling.

Known gaps (do not invent a workaround in docs):
  • Examples/Prompts/prompt_tools_then_structured.malda interprets offline; C# construct currently throws NullReferenceException. Ship row stays n/a.
  • In-process llama.cpp / LLamaSharp stream() is buffered (chunks from the final text), not live tokens.
  • policy { shell: approve } is not a workflow approval UI. It auto-approves only when MALDA_POLICY_APPROVE=1 or a host ApprovalCallback returns true; otherwise it denies.

23.1 Eval suites

A suite is a named group of eval cases. malda run / ordinary interpret skips suites (like property). Run them with malda eval. That is not malda test, which discovers property declarations and *.test.malda files — see 35. Property Testing.

Lookahead after case: case "title" { is a suite case; case Pattern: is a match arm.

schema Card {
    name: string;
}

prompt extract(raw) -> Card {
    user: raw;
}

suite "extract" {
    case "offline shape" {
        var checked = evalPrompt(extract("x"), dict { "name": "Ada" });
        expect(checked.ok);
    }
}

print("ok");

expect(cond) throws like assert when the condition is false. A failed expect fails that sample. validate still returns { ok, error } and does not throw on mismatch.

malda eval Examples/Prompts/eval_suite_offline.malda
malda eval path.malda --baseline .malda/evals.json
malda eval path.malda --baseline .malda/evals.json --update-baseline
  • @samples(N) — under MALDA_REPLAY, replay N recorded variants; without replay, N live samples. N <= 1 runs once.
  • @threshold(0.9) — exit non-zero when the case pass rate is below the threshold.
  • @judge(prompt gradeHelpfulness) — after a passing body, evaluate the judge expression (a prompt is called with the case title). A result object with ok: false fails the sample.
  • Comparing against an existing baseline also fails the process when a case pass rate drops.

Same file: Examples/Prompts/eval_suite_offline.malda. Agent snippet: docs/llm/few-shot/43_eval_suite.malda.

23.2 Cassettes

Every LLM Chat path (HTTP, GGUF, client bridge) goes through one record/replay gate. Cassettes are JSONL. Secrets (Authorization, API keys, obvious secret-shaped strings) are redacted on record.

MALDA_RECORD=tests/cassettes/name.jsonl   malda Examples/path.malda
MALDA_REPLAY=tests/cassettes/name.jsonl   malda Examples/path.malda
MALDA_REPLAY_STRICT=1                    malda Examples/path.malda

The cassette key is prompt hash + canonical args + model + mode (A/B/C) + schema hash. A replay miss journals cassette_miss. Without MALDA_REPLAY_STRICT=1 the host warns and falls through to a live call. Strict mode throws. How to record: tests/cassettes/README.md.

Examples/Agents/agent_governance_golden.malda is an offline interpret/transpile pair (no cassette). Examples/RalphWiggum/RalphWiggum.malda stays n/a (too-large).

23.3 Run journal

One in-process journal collects prompt, tool, cap, hop, and workflow-step events. Workflow SQLite remains the durability store; successful steps are also mirrored here so trace.journal() and workflow events share a substrate.

schema Card {
    name: string;
}

prompt extract(raw) -> Card {
    user: raw;
}

var checked = evalPrompt(extract("Ada"), dict { "name": "Ada" });
var events = trace.journal();
print(events.length > 0);

Each event is an object with ts, span, kind (prompt / tool / cap / hop / step), name, optional promptHash / model / tokens / cost / ms / repairs / error, and ok.

  • trace.span("name", fn) — nest events under that span name.
  • trace.lastUsage() — last recorded token/cost/ms object, or null.
  • .usage on a prompt result is metadata. An own object key named usage (schema field) wins.

Export: MALDA_TRACE=jsonl|otlp plus optional MALDA_TRACE_FILE. That is not the existing malda trace CLI, which still reads session .malda-trace.jsonl files. Same file: Examples/Prompts/run_journal_offline.malda.

23.4 within scopes

The statement within (30s) { … } is a wall-clock cancel scope. Units are a number plus ms, s, or m (converted to milliseconds). Optional budget(tokens: N, tools: N, cost: N?) pushes a nested resource budget like @budget.

The decorator @within(ms) remains the per-function / per-think deadline. It is not a statement and takes milliseconds only.

within (10ms) {
    sleep(50);
}

print("should-not-print");

On expiry the runtime journals a timeout and throws Timeout: exceeded within (…ms). Cancellation flows into LLM Chat and cap consume. Same file: Examples/Prompts/within_sleep.malda (interpret and C# both fail — a pair on error identity, not stdout).

  • race(tasks…) — first completed branch.
  • firstOk(tasks…) — first branch that is not a Timeout variant.
  • all(tasks…) waits for every branch. A failed branch becomes an AgentError Upstream slot; the call does not rethrow the first error.
  • cancelWorkflow(id) flips the instance to cancelled; the body polls that status between statements.

23.5 Declared context

A context Name { … } declaration is a schema-like mini-DSL. new Name() constructs a journaled object with .add and .turns.

context Session {
    budget: 800 tokens;
    pin: systemFacts;
    retain: last 2;
    evict: oldest;
}

var s = new Session();
s.add("user", "hi");
s.add("user", "there");
print(s.turns.length >= 1);
  • budget: N tokens — stored on the instance (informational pin).
  • pin: name, … — those turns stay.
  • retain: last N — turn window.
  • evict: oldest | lowestScore | none.
  • compact: prompt summarize — optional named prompt; compaction is a recorded model call (cassette-keyed) then evicts.

WF1006: compaction / context mutation inside a workflow body must sit in a step. Imported or unknown callees stay Info, same as WF1005. See 22. Durable Workflows.

23.6 Program-boundary policy

A file-level policy { … } is enforced on cap consume regardless of which tools the host registered. Violation journals a cap event and throws ToolDenied: ….

policy {
    fs:    readOnly under "./work";
    net:   allow "api.example.com", "*.internal";
    shell: deny;
    mcp:   allow "local";
}
  • deny — always refuse that domain.
  • allow / readOnly — optional path/host patterns; readOnly also refuses writes.
  • approve — requires MALDA_POLICY_APPROVE=1 (or true) or a host ApprovalCallback. There is no interactive workflow-style prompt yet.

@effects("pure") is still a static check (IO namespaces include cap). Policy is the runtime deny list. They are not the same mechanism.

23.7 AgentError

A built-in sum type, pre-registered:

AgentError = Refused(reason) | Unparsable(raw, attempts) | SchemaMismatch(schema, error)
           | BudgetExceeded(kind, limit) | ToolDenied(tool, reason) | Timeout(ms)
           | Upstream(status, body)

Existing { ok, error } strings stay. Throws stay throws. Sites that already return a result object also attach agentError as the variant. validate mismatch → SchemaMismatch.

schema Card { name: string; }
var r = validate("Card", dict { "email": "x" });
print(r.ok);

Read r.agentError for the tagged variant. Checking only the string error is still valid and still misses the tag.

23.8 Stream and for await

stream(value, schema?) yields an array of chunks { text }, or schema-aware partial objects when a registered schema name is passed. for await (var x in expr) iterates that collection (today the builtin materializes the array; C# emit is foreach over it).

var n = 0;
for await (var chunk in stream("hello world from malda")) {
    n = n + 1;
}
print(n > 0);

The incremental JSON prefix parser closes partial objects/arrays and yields the largest prefix that validates. LlamaCpp has no live token stream — chunks are carved from the finished text.

23.9 Grounded sinks

grounded.wrap(value, citations?) attaches citation metadata on the runtime value (not a new match kind). Interpolation and str.* union citation sets. Mixing grounded and ungrounded text marks the result partial.

var g = grounded.wrap("Ada", [{ "source": "wiki", "id": "1" }]);
var s = $"Hello {g}";
print(s.citations.length >= 1);

@requiresCitations on a function (and marked sinks such as io.writeFile / HTTP response) errors when a string argument has no citations. match / validate do not see a new type.

23.10 Check loop

malda check is still diagnose-only. --fix applies mechanical edits: flat stdlib aliases → namespaced calls, "total: {n}" → $"…", items.length() → items.length. --json diagnostics may include suggestedFix (did-you-mean). Not every gotcha is auto-fixed.

malda check app.malda --json
malda check app.malda --fix
malda prompts --diff .malda/evals.json

Diagnostic sources:

  • malda-gotcha — io.input EOF loops, AnsiConsole.markup without a newline, unused validate, arr.append, parseJson homograph, unknown borderStyle.
  • malda-tools — @Tool / @MCPTool with no type hints and no schema argument.
  • malda-agents — static team topology (literal graphs / plans only).

Optional @version("2026-09-01") on a prompt is an informational pin. malda prompts --diff compares prompt hashes between eval baseline files. Flat aliases and parseJson stay until a dedicated 2.0 MAJOR; --fix / gotchas are the prep.
