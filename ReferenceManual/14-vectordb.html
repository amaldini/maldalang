14. VectorDB

VectorDB is a built-in class for storing and searching high-dimensional vectors using cosine similarity. It's designed for efficient similarity search in applications like semantic search, recommendation systems, and machine learning embeddings.

14.1 Creating a VectorDB

VectorDB instances are created with the new VectorDB(...) constructor:

// Define a vector calculator function
function calculateVector(data) {
    // Your vector calculation logic here
    // Must return an array of numbers matching the dimension
    return [1.0, 2.0, 3.0, /* ... */];
}

// Create a VectorDB with dimension 127 and double precision
var v = new VectorDB(127, "double");

// Or with single precision (more memory efficient)
var v2 = new VectorDB(256, "single");

// Initialize with the calculator function
v.init(calculateVector);
v2.init(calculateVector);

Constructor Parameters:

  • dimension (integer): The dimension of all vectors (e.g., 127, 256, 768)
  • precision (string): Either "single" (float, 4 bytes per element) or "double" (double, 8 bytes per element)

Initializing the Calculator Function:

After creating a VectorDB, you must call init(calculatorFunction) to set the calculator function that will be used to calculate vectors from data:

var db = new VectorDB(26, "double");
db.init(calculateVector);  // Set the calculator function

The calculator function is used by add(data) and searchSimilar(data, topN) to automatically calculate vectors from data.

14.2 Adding Vectors

The add() method supports two ways to add vectors:

14.2.1 Adding with Automatic Vector Calculation

If a calculator function is set via init(), you can add data directly and the vector will be calculated automatically:

var v = new VectorDB(26, "double");
v.init(calculateVector);

// Add data - vector is calculated automatically
v.add("Hello");
v.add("World");
v.add(dict { "type": "string", "value": "Example" });

14.2.2 Adding with Explicit Vector

You can also provide the vector explicitly:

var v = new VectorDB(3, "double");

// Add a vector with associated data
v.add([1.0, 2.0, 3.0], "document1");
v.add([4.0, 5.0, 6.0], "document2");
v.add([7.0, 8.0, 9.0], dict { "id": "doc3", "title": "Example" });

Parameters:

  • add(data): Single argument - data to add. Requires calculator function to be set via init()
  • add(vector, data): Two arguments - explicit vector array and associated data
  • vector (array): An array of numbers matching the VectorDB dimension (required when using 2-argument form)
  • data (any): Any MALDA value to associate with the vector (string, object, number, etc.)

14.3 Similarity Search

Use searchSimilar(data, topN) to find the most similar vectors using cosine similarity. The calculator function must be set via init():

var v = new VectorDB(128, "double");
v.init(calculateVector);

// Add some vectors
v.add("document1");
v.add("document2");
v.add("document3");

// Search for similar vectors
var results = v.searchSimilar("query text", 5);

// Results is an array of objects with:
// - vector: The original vector array
// - data: The associated data
// - similarity: Cosine similarity score (0.0 to 1.0)
foreach (var result in results) {
    print("Data: " + result.data);
    print("Similarity: " + result.similarity);
}

How it works:

  • The calculator function is called with the query data to generate a query vector
  • Cosine similarity is calculated between the query vector and all stored vectors
  • Results are sorted by similarity (descending) and the top N are returned
  • Similarity scores range from -1.0 to 1.0, with 1.0 being identical vectors

14.4 Binary Serialization

VectorDB supports efficient binary serialization for persistence and large datasets:

var v = new VectorDB(127, "double");
v.init(calculateVector);

// Add vectors...
v.add("data1");
v.add("data2");

// Serialize to binary file
v.serialize("vectordb.bin");

// Later, deserialize (calculator function is NOT stored)
var v2 = v.deserialize("vectordb.bin");

// Re-initialize with the calculator function
v2.init(calculateVector);

Important Notes:

  • Binary format is much more efficient than JSON for large vector databases
  • The calculator function is NOT stored in the serialized file
  • After deserialization, you must call init(calculatorFunction) to set the calculator function
  • This allows you to use different calculator functions with the same serialized data if needed
  • The serialized format stores only vectors and associated data, not the calculator function

14.5 Complete Example

// Define a simple vector calculator
function simpleVectorCalc(text) {
    // Simple example: create a vector from text length and first few characters
    var vec = [];
    var len = length(text);
    for (var i = 0; i < 10; i = i + 1) {
        if (i < len) {
            var char = substring(text, i, 1);
            vec.append(charCodeAt(char, 0) / 100.0);
        } else {
            vec.append(0.0);
        }
    }
    return vec;
}

// Create VectorDB
var db = new VectorDB(10, "double");

// Initialize with calculator function
db.init(simpleVectorCalc);

// Add documents - vectors calculated automatically
db.add("Hello world");
db.add("Hello there");
db.add("Goodbye world");

// Search for similar documents
var results = db.searchSimilar("Hello", 2);
print("Top 2 similar documents:");
for (var i = 0; i < results.length; i = i + 1) {
    print("  " + (i + 1) + ". " + results[i].data + " (similarity: " + results[i].similarity + ")");
}

// Serialize for later use
db.serialize("my_vectordb.bin");

// Deserialize later
var db2 = db.deserialize("my_vectordb.bin");

// Re-initialize with calculator function
db2.init(simpleVectorCalc);

14.6 Built-in Text Embeddings

MALDA provides built-in text embedding functions that can be used as VectorDB calculator functions. These functions calculate embeddings on-the-fly from text strings or files, without requiring neural networks.

Important: Using Embedding Functions with VectorDB

When using built-in embedding functions (like embedBagOfWords, embedHash, etc.) with VectorDB, you must create a wrapper function that provides the required parameters (like dimension). This is because:

  • VectorDB's calculator function is called with only the data (text) as an argument
  • Embedding functions require additional parameters (dimension, vocabulary, etc.)
  • The wrapper function "bakes in" these parameters, creating a function that matches VectorDB's expected signature: function(data) → array

Example pattern:

// Create wrapper function with dimension
function myEmbed(text) {
    return embedBagOfWords(text, 100);  // dimension is "baked in"
}

// Use wrapper with VectorDB
var db = new VectorDB(100, "double");
db.init(myEmbed);
db.add("Hello");  // myEmbed is called automatically
var results = db.searchSimilar("world", 5);  // myEmbed is called automatically

Bag-of-Words Embedding

embedBagOfWords(text, dimension?, vocabulary?) creates word frequency vectors:

// Create a wrapper function that provides the dimension
function bagOfWordsEmbed(text) {
    return embedBagOfWords(text, 1000);
}

// Use the wrapper function with VectorDB
var db = new VectorDB(1000, "double");
db.init(bagOfWordsEmbed);
db.add("Hello world");
db.add("Hello there");
var results = db.searchSimilar("world", 5);

// With custom vocabulary
var vocab = ["machine", "learning", "artificial", "intelligence"];
function vocabEmbed(text) {
    return embedBagOfWords(text, vocab.length, vocab);
}
var db2 = new VectorDB(vocab.length, "double");
db2.init(vocabEmbed);

Parameters:

  • text (string or array): Text content or array of strings/file paths
  • dimension (integer, optional): Vector dimension (default: 1000)
  • vocabulary (array, optional): Custom vocabulary array for exact matching

Character N-Grams Embedding

embedCharacterNGrams(text, n?, dimension?) creates character n-gram frequency vectors:

// Character trigrams (default n=3)
function ngramEmbed(text) {
    return embedCharacterNGrams(text, 3, 500);
}
var db = new VectorDB(500, "double");
db.init(ngramEmbed);
db.add("Hello");

Parameters:

  • text (string or array): Text content or array of strings/file paths
  • n (integer, optional): N-gram size (default: 3 for trigrams)
  • dimension (integer, optional): Vector dimension (default: 1000)

Hash-based Embedding

embedHash(text, dimension?) creates hash-based feature vectors:

// Hash-based embedding (compact, fixed dimension)
// Create a wrapper function that provides the dimension
function hashEmbed(text) {
    return embedHash(text, 128);
}

var db = new VectorDB(128, "double");
db.init(hashEmbed);
db.add("Hello world");
db.add("Hello there");

Parameters:

  • text (string or array): Text content or array of strings/file paths
  • dimension (integer, optional): Vector dimension (default: 128)

TF-IDF Embedding

embedTFIDF(text, corpus?, dimension?) creates TF-IDF (Term Frequency-Inverse Document Frequency) vectors:

// TF-IDF with corpus for IDF calculation
var corpus = ["file1.txt", "file2.txt", "file3.txt"];
function tfidfEmbed(text) {
    return embedTFIDF(text, corpus, 1000);
}
var db = new VectorDB(1000, "double");
db.init(tfidfEmbed);
db.add("machine learning");

// TF-IDF without corpus (uses only TF)
function tfidfEmbedNoCorpus(text) {
    return embedTFIDF(text, null, 1000);
}
var db2 = new VectorDB(1000, "double");
db2.init(tfidfEmbedNoCorpus);

Parameters:

  • text (string or array): Text content or array of strings/file paths
  • corpus (array, optional): Array of documents for IDF calculation
  • dimension (integer, optional): Vector dimension (default: 1000)

File-based Embedding

embedFromFile(filePath, method, ...) reads a file and embeds it:

// Embed from file using different methods
var vec1 = embedFromFile("document.txt", "bagOfWords", 1000);
var vec2 = embedFromFile("document.txt", "characterNGrams", 3, 500);
var vec3 = embedFromFile("document.txt", "hash", 128);
var vec4 = embedFromFile("document.txt", "tfidf", corpus, 1000);

// Embed multiple files
var filePaths = ["doc1.txt", "doc2.txt", "doc3.txt"];
var embeddings = embedFromFiles(filePaths, "bagOfWords", 1000);
// Returns array of vectors, one per file

Parameters:

  • filePath (string): Path to file
  • method (string): Embedding method ("bagOfWords", "characterNGrams", "hash", "tfidf")
  • Additional arguments: Passed to the embedding method

Embedding Features

  • Automatic File Reading: Functions accept strings or file paths - if a string looks like a file path, it's automatically read
  • L2 Normalization: All embeddings are L2-normalized for proper cosine similarity
  • Feature Hashing: Vocabulary-free embeddings use deterministic hash functions (FNV-1a)
  • Tokenization: Words are split on whitespace and punctuation, converted to lowercase
  • Memory Efficient: No vocabulary storage required for hash-based methods

Complete Embedding Example

// Example: Document search with TF-IDF
var documents = [
    "Machine learning is a subset of AI",
    "Vector databases enable semantic search",
    "Natural language processing uses neural networks"
];

// Create corpus for IDF calculation
var corpus = documents;

function tfidfEmbed(text) {
    return embedTFIDF(text, corpus, 1000);
}

// Create VectorDB with TF-IDF embeddings
var db = new VectorDB(1000, "double");
db.init(tfidfEmbed);

// Add documents - vectors calculated automatically
for (var i = 0; i < documents.length; i = i + 1) {
    db.add(documents[i]);
}

// Search for similar documents
var results = db.searchSimilar("artificial intelligence", 3);
for (var i = 0; i < results.length; i = i + 1) {
    print((i + 1) + ". " + results[i].data + " (similarity: " + formatNumber(results[i].similarity, 4) + ")");
}

14.6.1 Neural Network Embeddings with LLamaSharp

While built-in embedding functions (bag-of-words, hash, TF-IDF) are fast and don't require external dependencies, neural network embeddings from LLM models provide superior semantic understanding. MALDA supports neural network embeddings through the LlamaEmbedder class, which uses LLamaSharp to generate embeddings from local GGUF embedding models.

Why Use Neural Network Embeddings?

Neural network embeddings offer several advantages over traditional text-based embeddings:

  • Semantic Understanding: Neural networks understand context, synonyms, and semantic relationships. For example, "car" and "automobile" will have similar embeddings even though they share no characters, while "car" and "cat" will be more distinct despite sharing letters.
  • Context Awareness: The same word in different contexts produces different embeddings. "Bank" (financial institution) vs "bank" (river edge) are correctly distinguished.
  • Cross-Lingual Support: Many embedding models support multiple languages and can find semantic similarity across languages.
  • Better Search Quality: Semantic search with neural embeddings finds conceptually similar content, not just textually similar. A query for "feline pets" will find documents about "cats" even if the word "cat" never appears.
  • Domain Adaptation: Pre-trained models have learned from vast amounts of text, capturing general language understanding that works across domains.

When to Use Neural Embeddings vs Built-in Embeddings:

  • Use Neural Embeddings for: Semantic search, RAG (Retrieval-Augmented Generation), document similarity, question-answering systems, recommendation systems, and any application where understanding meaning is more important than exact word matching.
  • Use Built-in Embeddings for: Fast prototyping, exact keyword matching, when you don't have embedding models available, memory-constrained environments, or when speed is more critical than semantic accuracy.

Using LlamaEmbedder with VectorDB

// Load an embedding model (e.g., nomic-embed-text-v1.5, bge-small, etc.)
var embedder = new LlamaEmbedder("path/to/embedding-model.gguf");

// Create a wrapper function for VectorDB
function neuralEmbed(text) {
    return embedder.getEmbeddings(text);
}

// Create VectorDB with dimension matching your model
// Common dimensions: 384 (nomic-embed-text), 768 (bge-small), 1024, 4096
var db = new VectorDB(384, "single");  // Match your model's output dimension
db.init(neuralEmbed);

// Add documents - embeddings calculated using neural network
db.add("Machine learning is transforming industries");
db.add("Artificial intelligence enables new capabilities");
db.add("Neural networks learn from data");

// Semantic search - finds conceptually similar content
var results = db.searchSimilar("AI technology", 3);
// Will find "Artificial intelligence enables new capabilities" even though
// "AI" doesn't appear in the stored text

Using LlamaEmbedder with GraphMemory

// Initialize embedder
var embedder = new LlamaEmbedder("path/to/embedding-model.gguf");

// Create embedding function
function neuralEmbed(text) {
    return embedder.getEmbeddings(text);
}

// Initialize GraphMemory with custom embedding function
var memory = new GraphMemory();
memory.initialize(384, "single", neuralEmbed);  // 3rd parameter: embedding function

// Store facts - uses neural embeddings for better semantic understanding
memory.remember("I work as a software engineer");
memory.remember("I develop applications using Python");

// Query with semantic understanding
var results = memory.query("What is my profession?", 5);
// Will find both facts because "software engineer" and "develop applications"
// are semantically related to "profession"

Model Selection:

  • Small Models (384-512 dim): Fast, memory-efficient, good for most use cases (e.g., nomic-embed-text-v1.5, bge-small-en-v1.5)
  • Medium Models (768-1024 dim): Better accuracy, more memory (e.g., bge-base-en-v1.5, e5-base-v2)
  • Large Models (2048+ dim): Best accuracy, requires significant memory (e.g., bge-large-en-v1.5)

Performance Considerations:

  • Neural embeddings are slower than built-in embeddings (typically 10-100ms per text vs <1ms)
  • Models require memory (typically 100MB-2GB depending on size)
  • First embedding call loads the model (may take several seconds)
  • Subsequent embeddings are faster once the model is loaded
  • Use GPU acceleration (setGpuLayerCount()) for faster inference if available

14.7 Retriever (asRetriever)

VectorDB instances can expose a retriever for document-oriented RAG pipelines. Call asRetriever(options?) to get an object with get and getFormatted methods:

function embedText(text) {
    return embedBagOfWords(text, 16);
}

var vdb = new VectorDB(16, "single");
vdb.init(embedText);

indexInto(vdb, [
    { content: "GraphMemory stores facts.", metadata: { source: "memory.md" } }
]);

var retriever = vdb.asRetriever({ topK: 3, minScore: 0.1 });

// get(query) → array of { content, metadata } documents
var docs = "GraphMemory" |> retriever.get;

// getFormatted(query) → single string for prompt context
var context = question |> retriever.getFormatted;

Options:

  • topK (integer): maximum number of hits to return (default: 4)
  • minScore (number): minimum cosine similarity threshold (default: 0.0)

When documents are indexed with indexInto, metadata (including source) is preserved in search results and included by formatRetrievedDocs.

Combine with prompts and pipes — see Examples/Prompts/rag_pipeline.malda and 7. Expressions (pipe operator).

14.8 Use Cases

VectorDB is useful for:

  • Semantic Search: Find documents similar to a query based on embeddings
  • Recommendation Systems: Find similar items based on feature vectors
  • Machine Learning: Store and search embedding vectors from ML models
  • Image Search: Find similar images based on visual feature vectors
  • Anomaly Detection: Find vectors that are dissimilar to normal patterns

14.8.1 Real-World VectorDB Applications

Vector databases are transforming industries across the globe. Here are 10 major applications:

  1. Supercharged Search Engines

    Vector databases enable semantic search that understands the true meaning behind user queries, accounting for synonyms and context. This results in more relevant and personalized search results.

    Example: Spotify uses vector databases to power its search function by analyzing audio features and user listening habits as vectors, recommending music that aligns with your taste even when searching with descriptive terms.

  2. Fraud Detection

    Financial institutions use vector databases to analyze transaction patterns in real-time. By representing transactions as vectors with data points like amount, location, and user behavior, they can identify anomalies and suspicious activities.

    Example: PayPal uses these databases to prevent fraud by identifying unusual patterns that deviate from normal behavior and flagging suspicious actions after analyzing large volumes of past legitimate transactional information.

  3. Product Recommendations

    E-commerce platforms thrive on personalized recommendations. Vector databases analyze user purchase history, product attributes, and customer reviews as vectors to recommend products with high accuracy.

    Example: Amazon analyzes past purchases, browsing behavior, and product reviews as vectors to suggest items likely to interest customers, keeping them engaged and increasing sales.

  4. Music Recommendation Systems

    The music industry uses vector databases to analyze audio features like rhythm, melody, and genre as vectors, enabling streaming services to recommend music that perfectly caters to individual taste.

    Example: SoundCloud's music discovery features are powered by vector databases, using audio features of songs you've listened to and vectors of user preferences to provide recommendations in the same sonic palette.

  5. Computer Vision & Image Recognition

    Vector databases are the backbone of applications that analyze images and videos. By storing and searching image features as vectors, they enable tasks like facial recognition, object detection, and content moderation.

    Example: Facebook uses vector databases for its facial recognition feature, converting facial features into vectors and comparing them to a database of user profiles to automatically suggest photo tags.

  6. Drug Discovery

    The pharmaceutical industry uses vector databases to accelerate drug discovery. These databases store and analyze molecular structures as high-dimensional vectors, allowing researchers to quickly find potential drug candidates.

    Example: GlaxoSmithKline (GSK) leverages vector databases in their drug discovery efforts, analyzing properties of existing drugs and potential targets as vectors to identify molecules with desired therapeutic effects.

  7. Personalized Learning Platforms

    The education sector uses vector databases to store student performance data, learning styles, and content attributes as vectors, enabling personalized learning platforms that recommend materials and adapt to individual needs.

    Example: Duolingo utilizes vector databases to personalize language learning experiences, analyzing progress on lessons, strengths, and weaknesses as vectors to tailor learning paths that maximize progress.

  8. Genomics Research

    Genomic research generates massive datasets. Vector databases analyze these by representing genes and their interactions as vectors, allowing researchers to identify patterns and relationships that could unlock new medical knowledge.

    Example: Broad Institute leverages vector databases to analyze genetic data in cancer research, representing gene mutations and patient profiles as vectors to identify patterns correlating with specific types of cancer.

  9. Natural Language Processing (NLP)

    Vector databases store and retrieve word embeddings, which are numerical representations that capture the meaning and connections between words, enabling advanced NLP applications.

    Example: Netflix utilizes vector databases to power its recommendation system for shows and movies, analyzing descriptions, cast information, and user viewing habits as vectors to recommend content aligned with preferences.

  10. Cybersecurity

    Vector databases are crucial tools in the fight against cyber threats. By storing network traffic data as vectors, they can analyze them in real-time to detect anomalies or intrusions that may occur unnoticed.

    Example: Cloudflare utilizes vector databases to detect distributed denial-of-service (DDoS) attacks, analyzing network traffic patterns as vectors to identify unusual spikes in traffic that may indicate an attack.

14.9 Performance Considerations

  • Precision: Use "single" for memory efficiency, "double" for higher precision
  • Binary Serialization: Much faster and more compact than JSON for large databases
  • Cosine Similarity: Efficiently calculated using optimized C# arrays
  • Search Performance: Linear search through all vectors - consider indexing for very large datasets
